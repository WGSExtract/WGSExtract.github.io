Privacy and network access (Desktop App)

Whole-genome data is deeply personal and uniquely identifying — for you and for your biological relatives. All genomic analysis in WGS Extract runs locally on your computer. Your FASTQ, BAM, CRAM, VCF, microarray files, genotypes, and variant coordinates are never uploaded by default, and there is no analytics tracking or usage telemetry.

This guide explains how network access works in the WGS Extract desktop app, how it differs from the stricter CLI back-end, what external servers can see when you check for updates or download public data, and how to run completely offline.

For the full command-by-command audit of the CLI engine, see the CLI Privacy and network access guide. For the architectural contract between the app and the CLI, see Architecture — Privacy and network boundary.

How the Desktop App and CLI work together#

WGS Extract intentionally separates two different user needs across two layers:

  1. The CLI back-end (wgsextract) is strictly offline by default. Ordinary analysis, inspection, and reporting commands never contact the internet, never check for updates, and never install missing files or tools silently. Every CLI network call requires either an explicit install/download subcommand (ref, deps install, vep download) or an explicit opt-in flag (--download, --online, or allow_reference_downloads = true).
  2. The Desktop App acts as an interactive assistant on your behalf. Casual (Basic mode) desktop users usually want the app to notify them when a newer version is available and to help fetch a missing reference genome or gene map with one click instead of failing with a cryptic error. The desktop app never silently turns on CLI auto-downloads behind your back; instead, it separates network behavior into four transparent tiers.

What external servers can see (IP address & metadata)#

Even when no DNA or sample information leaves your computer, any internet request naturally reveals basic network metadata to the host you connect to:

  • Your public IP address (which can reveal approximate location or ISP)
  • Timing of the request
  • Standard HTTP headers (such as user-agent / platform)
  • Which public file, tool, or release was requested (for example, checking whether a newer WGS Extract release exists, or downloading the public hs38 reference genome or ClinVar release)

This applies to automatic update checks as well as manual downloads:

  • App update checks contact the configured GitHub release / updater feed (github.com / GitHub CDN) to compare your installed app version and platform/architecture against the latest release. They never transmit sample filenames, file paths, or genomic data.
  • Planned Reference Data, Reference Genomes, and Tools update checks follow the same rule: lightweight read-only metadata checks that report when a newer public database (such as ClinVar or yBrowse) or tool release is available, without downloading multi-gigabyte files until you explicitly click to update, and governed by the same Privacy mode switch in Settings.
  • Public downloads contact the upstream publisher (such as GitHub releases, Pixi/Conda/PyPI registries, NCBI, UCSC, EBI/Ensembl, Broad/gnomAD, Zenodo, or yBrowse) or an audited WGS Extract mirror. See the complete destination table in CLI Privacy — What goes where.
  • Documentation hot-links (https://wgse.bio/wgsextract-cli/...) open in your web browser only when you click them. Your browser's own privacy settings apply.

Local-only guarantees#

  • Loopback-only app communication: The desktop window and its local Node backend communicate strictly over authenticated 127.0.0.1 loopback sockets on your computer.
  • Self-contained reports and cards: HTML result cards and personal reports do not load remote scripts, fonts, or images automatically.
  • No silent allow_reference_downloads: On Settings (Advanced mode → Users Workspace Settings), Allow missing public-data downloads is off by default and stays off unless you explicitly enable it.
  • No automatic remote size probes: Opening Reference Genomes uses local catalog metadata and cached sizes only; remote size lookup runs only if you explicitly invoke and confirm Look up sizes.
  • Local Genome Viewer & Gene Page: Both run offline against files on your machine. The optional remote Genome Viewer never connects without your explicit connection and transfer confirmation, keeps your server token out of browser-delivered data, and enforces HTTPS certificate validation.

How to run completely offline#

If you work in an air-gapped environment or want zero outbound network traffic — including no IP-visible update checks:

  1. Turn on Privacy mode in Settings → Standard UI Options. The app then skips its startup update check and shows a red PRIVACY badge under its name. File → Check for Updates... still checks when you choose it. Future Reference Data, Reference Genomes, and Tools update checks will honor the same switch.
  2. Keep Allow missing public-data downloads turned off in Settings → Users Workspace Settings (this is already the default).
  3. Pre-install the tools, reference genomes, and reference data you need while online (using Setup, Tools, Reference Genomes, and Reference Data).
  4. Optionally verify readiness before disconnecting by running wgsextract deps ready -- <command ...> in a terminal — it checks every tool, genome, index, and database completely offline. See Checking a run before going offline.
