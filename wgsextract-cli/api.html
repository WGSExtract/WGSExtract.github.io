Python API

Call the same operations as the CLI using typed Python parameters.

The typed Python API of WGS Extract.

Every operation takes a frozen *Params dataclass and returns a Result (the wgsextract.result/1 manifest model the CLI writes):

from pathlib import Path
from wgsextract_cli import api

res = api.vcf.snp(api.VcfSnpParams(input=Path("x.cram"), region="chrM"))
res.outputs, res.metrics, res.warnings

Operations raise CommandFailed (carrying the failed Result) unless called with check=False. They accept a progress callback and a CancelToken. Operations that write files or run long run one at a time per process; quick read-only ones (info, info chip, lookup, sample show, ref status, ref recheck, ref library-list, report-delta, example-genome list, deps check) may run on several threads at once, each call with its own result, progress, cancellation and settings, unless asked to save files (info with detailed or table_format, ref library-list with remote_sizes, ref recheck with online), which makes them one at a time too. They write the same output files and manifests as the CLI but print nothing to stdout: the human-readable report the CLI would print is in Result.text instead, and external tools' stdout goes to stderr. Stdout itself is left alone, so the caller's own writes (including from a progress callback or other threads) still reach it, e.g. a stdio JSON-RPC server.

Unset fields with a config.toml setting take it, as on the CLI. The user's config.toml is loaded on the first call; use_config(path) selects another for the process (from anywhere, a scoped_config block included), and with scoped_config(path): one for the calls made in the block, on that thread and the worker threads they start.

The CLI is built on this layer: each migrated command's options are generated from its Params fields, so the API and --help cannot drift.

Stability: the names exported here and the group modules (api.extract, api.info, api.bam, api.qc, api.align, api.vcf, api.lineage, api.methylation, api.microarray, api.panel, api.ref, api.repair, api.genotyping, api.report, api.lookup, api.sample, api.support, api.pet, api.analyze, api.sign, api.deps, api.examples, api.vep, api.benchmark, api.score, api.fastq) follow semantic versioning from the 1.0 release; adding fields with defaults is not a breaking change. Modules whose names start with _ are private and may change at any time.

Results, progress and cancellation

api.Result is the CommandResult model of the result manifest: status, exit_code, error, inputs, outputs, metrics, warnings, details, manifest and provenance; to_dict() and to_json() give the wgsextract.result/1 document. text is the human-readable report the CLI prints (without --json); it is not in the manifest. api.json_schema(cls) gives a JSON Schema of a Params class. Start with the compact index wgsextract help --all --json, then wgsextract help <command> --json includes the typed command's input_schema, with each property's flag as x-cli-flag (a positional argument's metavar as x-cli-positional).

api.ProgressEvent

One progress report: a stage name, a message and, when known, how far through the operation is (0.0 to 1.0).

Stages so far: start and finish (the command name, 0.0 and 1.0), tool (an external tool is starting), step (a resumable workflow runs or skips one of its steps, and why), heartbeat (a periodic count from a long tool run, such as "1,200/5,000 reads", with the fraction of that run done when the total is known) and contig (a per-contig worker finished, such as "chr2 (3/25 contigs)", with the fraction of the contigs' bases done so far, or of the contigs when their lengths are not known, as in microarray). More stages may be added.

api.ProgressCallback

Receives progress events, from the calling thread or a worker thread.

api.CancelToken

Cooperative cancellation of a running operation.

cancel() may be called from any thread. It stops the operation's external tools at once and makes the operation fail as cancelled at its next checkpoint. A token belongs to one operation.

  • is_set: Alias of cancelled, so a token works where a threading.Event does.
  • on_cancel: Call callback on cancellation (at once if already cancelled); returns a function that unregisters it.

api.CommandFailed

An operation failed; result holds the error, warnings and partial outputs.

api.vep

vep: annotate variants with a Variant Effect Predictor (VEP): vep-rs, or Ensembl VEP.

run annotates a VCF, BCF, BAM or CRAM, or every such file in a folder. A BAM or CRAM is first called with bcftools against ref. Each input gets <input stem>_vep.vcf.gz (or .txt/.json with format) and VEP's summary in outdir, else beside the input; an input whose output already exists is skipped unless force. CLI: wgsextract benchmark.

Run the benchmark (see BenchmarkParams).

BenchmarkParams: Benchmark the operations on generated or real data (see the module docstring). coverage, full_size, region and target_count default to the profile's; threads overrides the machine's tuned count for every step.

Field Type Default CLI Description
outdir Path | None None --outdir, -o Folder for the benchmark runs (default: out/benchmark in the working folder; config output_directory doesn't apply).
threads int | None None (config cpu_threads) --threads, -t CPU threads; None picks a count for this machine (default: config cpu_threads, else auto).
memory str | None None (config memory_limit) --memory, -m Memory per thread, e.g. '2G' (sorts: at most half the RAM in all); None picks a share of RAM (default: config memory_limit, else auto).
profile str 'standard' --profile Benchmark size preset. smoke is chrM-only, standard is a scaled human-like genome, 200mb targets a ~200 MiB fake BAM, and full uses real chromosome lengths. One of: 200mb, full, smoke, standard
coverage float | None None --coverage Override generated BAM coverage for the selected profile.
full_size bool False --full-size Use real chromosome lengths for the generated benchmark reference.
build str 'hg38' --build Generated reference naming/build convention. One of: 38, grch38, hg38, hs38, hs38d1, hs38d1v0, hs38dh, GRCh38, hs38DH, 37, grch37, hg19, hg37, hs37, hs37d5, GRCh37, chm13, chm13v2, chm13v2.0, t2t, t2tv2, t2tv2.0, t2tv20, T2Tv20, T2Tv2, T2Tv2.0, CHM13, CHM13v2.0
seed int 20260504 --seed Random seed for deterministic benchmark data generation.
target_count int | None None --target-count Approximate number of target SNPs for the microarray benchmark.
region str | None None -r, --region Optional region to benchmark for region-aware operations.
keep_going bool False --keep-going Continue independent benchmark steps after a failed step when possible.
suite str 'heavy' --suite Benchmark operation coverage. core runs the lighter baseline suite. One of: core, heavy
dataset str 'fake' --dataset Benchmark foundation data. fake generates synthetic data; real uses the release-backed mini genome zip; real-1x and real-30x cache public 1000 Genomes WGS references locally. One of: fake, real, real-1x, real-30x
dataset_zip Path | None None --dataset-zip Local real benchmark dataset zip. Overrides --dataset-url when --dataset real is used.
dataset_url str 'https://github.com/WGSExtract/wgsextract-cli/releases/download/v0.1.0/wgsextract-benchmark-hg19-mini.zip' --dataset-url URL for the release-backed real benchmark dataset zip used by --dataset real.
dataset_sha256 str | None 'ad0f8070dc5ca35c4a6de540493a81df082d160417f747ae68d9c098c110a9f6' --dataset-sha256 Expected SHA-256 of the dataset zip; empty or None checks none.
dataset_cache_dir Path | None None --dataset-cache-dir Folder for cached real dataset downloads (default: the dev download cache when enabled, else <outdir>/datasets).
