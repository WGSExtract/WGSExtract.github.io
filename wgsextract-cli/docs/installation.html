CLI installation and removal

For the platform walkthrough, see the site install guide. For source development, use developer setup instead.

Install#

macOS and Linux x86_64 or native ARM64 (linux-aarch64):

curl -fsSL https://raw.githubusercontent.com/WGSExtract/wgsextract-cli/main/install.sh | sh

The bootstrap script comes from main, but installs the latest published GitHub release, not main. It creates wgsextract-cli/ in the current directory (or beside a downloaded install.sh) with the app in app/, Pixi files in .pixi/, and the wgsextract launcher and uninstall.sh. On macOS it checks for Xcode Command Line Tools first. When upgrading, the installer restores the previous app if Pixi setup or verification fails. A successful upgrade rebuilds the default environment. If the Pixi environment location stays the same, optional environments are kept. The installer refuses to move existing local optional environments to a detached location because their installed files can contain absolute paths.

Linux ARM64 phase 1 supports default alignment/CRAM/calling/export, VEP, native Yleaf-derived Y-DNA analysis and Haplogrep 3. GATK fails before execution because its native kernels are not yet qualified. DeepVariant has an explicit native CPU source-build path; there is no silent Java or x86-emulation fallback. See Linux ARM64. Releases v0.6.5 and earlier lack ARM64 support. To test unreleased support instead of a release, select main explicitly:

curl -fsSL https://raw.githubusercontent.com/WGSExtract/wgsextract-cli/main/install.sh | WGSEXTRACT_REF=main sh

On Windows, clone or download the repository and run install_windows.bat from PowerShell. It installs Pixi if missing, then the CLI and WGS Extract's native builds of samtools, bcftools, BWA, bwa-mem2, minimap2, fastp and samblaster into Pixi. The standalone installer checks the downloaded source archive in a private staging directory before copying it into the install directory. No WSL or MSYS2 is needed. See Windows.

Installer options#

These are installer inputs, not runtime CLI configuration. Set them before running install.sh:

VariableDefaultPurpose
WGSEXTRACT_INSTALL_DIRwgsextract-cli next to install.sh, or ./wgsextract-cli for curl | shInstall location
WGSEXTRACT_RELEASE_TAGlatest GitHub releaseRelease tag, or latest
WGSEXTRACT_REFWGSEXTRACT_RELEASE_TAGGit ref, or latest
WGSEXTRACT_ARCHIVE_URLGitHub source archive for WGSEXTRACT_REFExact source archive URL
WGSEXTRACT_BIN_DIR$WGSEXTRACT_INSTALL_DIRCLI launcher directory
WGSEXTRACT_PIXI_HOME$WGSEXTRACT_INSTALL_DIR/.pixi when Pixi is missingInstall SHA-256-verified pinned Pixi here; an existing Pixi on PATH or in ~/.pixi is reused
WGSEXTRACT_PIXI_CACHE_DIR$WGSEXTRACT_INSTALL_DIR/.pixi/cachePixi package cache
WGSEXTRACT_PIXI_ENV_DIR$WGSEXTRACT_INSTALL_DIR/app/.pixi/envsPixi environment location
WGSEXTRACT_NO_OPENunset1 skips opening Finder on macOS

Leave WGSEXTRACT_BIN_DIR, WGSEXTRACT_PIXI_HOME, WGSEXTRACT_PIXI_CACHE_DIR and WGSEXTRACT_PIXI_ENV_DIR unset to keep the installation together. Pin WGSEXTRACT_RELEASE_TAG=vX.Y.Z for reproducible installs; use WGSEXTRACT_REF=main or WGSEXTRACT_ARCHIVE_URL=<url> for testing.

When Pixi is missing, installers verify the pinned release's SHA-256 before running it; they do not execute unsigned upstream installer scripts. Updating the Pixi pin also requires updating its trusted release digests. Reference installation has separate sequence-dictionary checks.

Running#

Guides write plain wgsextract; substitute your launcher. Optional environments require explicit setup; the CLI never installs tools during a feature run.

macOS: OpenMP Error #15 with “unknown library”#

An interrupted process can leave an unwritten LLVM OpenMP registration in /private/tmp. If macOS reuses that PID, OpenMP may report a duplicate runtime even when the new process loaded only one. The locked WGS Extract and PharmCAT environments use Accelerate for bcftools on macOS to avoid this startup path. Other environments can still load OpenMP, including STRkit, phasing, SMN, Somalier, FreeBayes, LongTR, bwa-mem3, Clair3, Cyrius and VEP. This can also affect GATK when it loads Homebrew's libomp.

If the error persists, quit affected tools and inspect the entries with ls -l /private/tmp/__KMP_REGISTERED_LIB_*. For an individual entry, confirm it belongs to your account, is a regular file (not a symlink), and is empty or entirely zero-filled (hexdump -C shows its contents). Use ps -p PID with the numeric suffix and leave the file alone if that PID is active or if you are unsure. If the PID is absent, recheck immediately before deleting only that exact file with rm /private/tmp/__KMP_REGISTERED_LIB_PID (replace PID with the actual suffix). Never use sudo or a wildcard for removal. The CLI does not sweep the system temporary directory during normal use.

Uninstall#

./wgsextract-cli/uninstall.sh --yes

This removes the installation, launcher, Pixi environments and cache under it, including reference data in the default app/reference/ location. Updating by rerunning the installer instead keeps app/reference/, app/genomes/ and Pixi environments.

Configuration is kept unless --remove-config is given. Interactive runs ask whether to remove Pixi from ~/.pixi; --yes keeps it unless you add --remove-pixi. That also removes Pixi's PATH line from shell profiles, and deletes a profile such as ~/.zshrc only if installation created it and nothing else was added.

Custom WGSEXTRACT_BIN_DIR, WGSEXTRACT_PIXI_CACHE_DIR and WGSEXTRACT_PIXI_ENV_DIR locations are recorded at install time. --bin-dir, --pixi-cache-dir and --pixi-env-dir override those records. Other Pixi projects may share those directories, so outside the installation the uninstaller deletes only this installation's environment folder from the environment directory (and the directory itself if the installer created it and it is now empty), and deletes the cache directory only if the installer created it and it holds no Pixi environments. Before asking to continue, it lists exactly what it will delete, including config files and Pixi when --remove-config and --remove-pixi are given. Use --keep-pixi-cache and --keep-pixi-envs to keep this installation's external cache and environments; these flags do not preserve files inside the installation being removed. Windows has its own uninstaller.

On every platform, --remove-config includes the owned default users workspace's ~/wgs-extract/config.toml (%USERPROFILE%\wgs-extract\config.toml on Windows) and legacy per-user config locations. An otherwise empty default users workspace loses its ownership marker and directory too. Libraries, other files and their workspace marker are preserved; unmarked user folders are left alone. Without --remove-config, workspace configuration is unchanged.
