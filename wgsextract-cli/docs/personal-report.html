Personal report (wgsextract report)

wgsextract report summarises what earlier runs found for one sample in a single local report. It has three parts:

  • an HTML page, <sample>_personal_report.html;
  • the same content as Markdown, <sample>_personal_report.md;
  • the JSON document an agent or script can read, <sample>_personal_report.json, plus a findings table, <sample>_personal_report_findings.tsv (or .parquet with --format parquet).
wgsextract report --genome HG002            # a dataset-library folder
wgsextract report --input HG002/HG002.cram  # the input's folder
wgsextract report --workspace HG002 --results ~/wgs-out/HG002

The report is built from the result manifests (*.manifest.json, see result-manifest.md) that commands left in the sample folder, searched recursively, and from the sample workspace (sample-workspace.md). It runs no analysis. Run the analyses first; the report shows each section that has no run as not run, with the command that produces it.

When results were written elsewhere (--outdir or the output_directory setting), name that folder with --results DIR. The report's own output folder is always read. Only runs whose inputs are files in the sample folder, or outputs of runs already used, are taken from those folders, so a shared output folder doesn't mix samples. When a command ran more than once, the newest successful run is used. A section whose only runs failed is shown as failed, with the error.

When this sample's newest run of a step failed (or was cancelled) after an older one succeeded, the section keeps the older evidence but says so: a Newer attempt failed line at the top of the section names the newest attempt, its finish time and error, and the date of the run shown, and the section's sources list both runs with their status and finish time. The JSON adds a newer_attempt_failed warning and the newest attempt as the source's latest_attempt; the report's own manifest repeats the warning. Rerun the step (or delete the failed run's manifest) to clear it. Only runs this report already counts as this sample's are compared, so another sample's failures in a shared --results folder never mark a section stale.

With --input, only that file's connected runs are reported: runs on it, on files made from it (its vcf snp VCF, say), and the runs that made it. A PharmCAT run is also linked to runs that produced its --outside-call files. In a genome folder, which holds one person, runs on files made from no other alignment (a VCF from a lab, say) are included too. A per-file override does not make an ordinary folder single-sample. Without --input, a plain folder holding results of several samples is an error (exit 2) naming their input paths; choose one with --input. Matching filenames in different folders do not identify the same sample, and qc relate comparisons do not link samples for reporting. The report reads only manifests and the workspace, so it needs no samtools or other analysis tools, even for a BAM or CRAM --input.

Technical result, not diagnosis. The report describes what software found in this sequencing run. It is not a diagnosis or medical advice. Confirm any finding with an accredited clinical laboratory before acting on it.

Warnings the source runs recorded (low coverage, high no-call rates, ...) are shown with their section.

Repeat Expansions uses the latest successful typing str result for this sample. It does not run a repeat caller or read the alignment. A targeted --loci run only describes the selected loci; counts say nothing about the rest of the catalog. A locus can be both unconfirmed and flagged when clipped reads also suggest an expansion. Older manifests may report a flagged finding but lack its structured sizes, coverage or the normal count.

PharmCAT alternatives stay together as one ambiguous gene finding, rather than multiple ordinary genotypes. The JSON finding's pgx object records status (resolved, ambiguous, no_call), the alternative diplotypes and phenotypes, whether their phenotypes agree, and source: "PharmCAT". Conflicting or unknown phenotypes give no definitive guidance. Explicit unknown/no-call genes remain visible. Section counts distinguish uniquely resolved genes from ambiguous and no-call genes; alternative rows are not counted as genes. The evidence file and source manifest retain the result's provenance. Called haploid results, such as G6PD with no second allele, retain their single allele and known phenotype; an explicit Unknown allele remains a no-call.

vcf pharmcat consumes outside calls only when explicitly passed with --outside-call. Each invocation uses an isolated pipeline output directory; same-basename outside-call files left in the final output folder are not inputs. All requested outside-call files and their fingerprints are recorded as pharmcat_outside_call inputs in the result manifest, together with the merged pharmcat_outside_calls output. Repeatable merging still rejects duplicate genes.

Medication review (CPIC; not a prescription)#

--pgx-context FILE reviews the medications a person takes or is considering against CPIC guidance. The file is local TOML and is never uploaded:

# CPIC's generic names (or drug ids such as "RxNorm:2670"); population is
# CPIC's patient group or indication where its guidance depends on it.
medications = ["codeine", "paroxetine", { name = "clopidogrel", population = "NVI" }]
wgsextract report --genome HG002 --pgx-context medications.toml --download

The guidance comes from CPIC's database export, release v1.61.0 (CC0 1.0), pinned by SHA-256 and fetched from files.cpicpgx.org into <reference library>/report/cpic the first time, only with --download; without it the report stops and names the data. It is checked against its pin on every use, so a changed pin is never satisfied by an older copy.

Each medication gets one finding per gene combination CPIC's guidance uses. Its advisory.status says how far the evidence goes:

StatusMeaning
advisoryOne CPIC recommendation fits the confident call; it is quoted verbatim with CPIC's strength, the guideline, its PMID and the release. contraindication is true when it advises against the drug (avoid, not recommended, contraindicated, do not use).
context_reviewIt fits the genotype, but another listed medication may change the phenotype (below), or the recommendation says to avoid inhibitors of the gene and another listed medication inhibits it. alternatives holds the recommendations the change could lead to; the HTML and Markdown show them too, marked as not guidance for this person.
withheldThe call is weak (low or not_assessed evidence, a no-call) or ambiguous, and its possible results lead to different recommendations. Nothing is recommended.
context_neededCPIC's guidance differs by patient group or indication (clopidogrel, carbamazepine, phenytoin, ...); add population.
insufficient_evidenceNo CPIC recommendation applies: the drug isn't in CPIC, its gene pairs carry no prescribing guidance (CPIC level C/D), its guidance is an algorithm outside the recommendation table (warfarin), CPIC has none for this result, or none for the given population.
not_assessedA gene the guidance needs has no result; run vcf pharmcat (with the CYP2D6 or HLA outside calls).

The gate uses the evidence of the calls the guidance rests on, from the pharmacogenomics section before ambiguity lowers its label: a call needs high or moderate evidence to narrow CPIC's recommendations. A weak call counts as any of its possible results, so guidance is given only when CPIC has a recommendation for every possible result and it is the same for all of them; an ambiguous confident call counts as its alternatives, so phenotype-consistent alternatives give guidance and conflicting ones do not. Missing or partial reference evidence, unresolved Cyrius calls, the combined CYP2D6+CYP2D7 copy number and ambiguous PharmCAT alternatives therefore never become a single actionable result. A gene PharmCAT took from an outside call rests on that caller's finding in this report (Cyrius for CYP2D6, T1K for HLA): with none it is not_assessed (outside_call_unverified), and an outside call that differs from that caller's newest call (a resolved Cyrius diplotype, or T1K's alleles at PharmCAT's two-field resolution) is low (outside_call_mismatch).

Medication-adjusted phenotype. A listed medication changes a phenotype only through a rule in assets/report/pgx_context_rules.json (version 2026.11.1) that quotes CPIC; a rule applies only while the loaded CPIC release still carries its quote for the same drug, gene and phenotype. The one rule so far is paroxetine's CYP2D6 autoinhibition (CPIC SSRI guideline, PMID 37032427): a Normal Metabolizer may convert to an Intermediate or Poor Metabolizer and an Intermediate to a Poor one, dose-dependently; the effect in a Poor Metabolizer is minimal and in an Ultrarapid Metabolizer unclear. The section's genes list, and a finding per gene, give the genetic (baseline) and adjusted phenotype, the rule, the medication that triggers it, CPIC's quote and its recommendation id. A gene no listed medication affects is reported unchanged. Other interactions, doses and health factors are not assessed.

The section has the disclaimer "not a prescription": every finding says to review it with a clinician, and nothing should be started, stopped or changed without professional review. The report's manifest records the context file (pgx_context input) and CPIC export (cpic_data input) with their fingerprints, and the metrics cpic_release, cpic_sha256, pgx_rules_version, pgx_rules_sha256 and pgx_context_sha256 (a digest of the effective medication list); the JSON keeps the effective list. The review is rebuilt on every run, so a changed list or CPIC release always shows.

ClinVar gene list#

ClinVar findings show assertion review status and stars separately from sequencing confidence, together with the resource record ID. Conflicting assertions and their submitter distributions are explicitly labelled for review, never counted as consensus P/LP in carrier/biallelic gene status. The JSON variant's clinical_evidence object and the findings table's clinvar_* columns retain these fields. Phase-supported composed MNVs also retain mnv_components; their classified component calls do not count twice. See variant-confidence.md for normalization, phase requirements and the review-star scale.

ClinVar hits are listed only for the genes of one gene list, by default the 84 genes of the ACMG secondary-findings list, version 3.3 (Lee K et al., Genet Med 2025;27(8):101454, PMID 40568962). The genes, categories, inheritance and notes were checked against the paper's Table 1. v3.3 adds ABCD1, CYP27A1 and PLN to v3.2 and moves HFE to inborn errors of metabolism.

Pick another list with --gene-list or report_gene_list in config.toml:

  • A built-in list: acmg-sf-3.3 (the default) or acmg-sf-3.2. Built-in lists are assets of the GitHub release report-gene-lists-v3, pinned by SHA-256 in src/wgsextract_cli/assets/report/gene_lists.json. The report downloads a missing list only with --download permission, into report/gene_lists/ of the reference library, and checks it against the pinned SHA-256 whenever it reads it. Without a local list and permission, the command errors without connecting and asks for --download (see privacy). If an explicitly permitted download fails, the section warns (gene_list_unavailable) and places no calls; the other sections are unaffected.
  • A TSV file with a gene column, and optionally category, inheritance (AD, AR, SD, XL; see below), note, and spans (1-based, inclusive): hg19_chrom, hg19_start, hg19_end and the hg38_ columns, or chrom, start and end in the VCF's build. Lines starting with # are comments. The built-in lists use this format.
  • A BED file (.bed or .bed.gz) with the gene symbol in column 4, in the VCF's build. A gene keeps every interval, on any chromosome.

A call is placed in a gene by ClinVar's own gene symbols (GENEINFO, which vcf clinvar carries over when the ClinVar file has it). For calls annotated without GENEINFO, it is placed by the gene spans, in the build of the VCF vcf clinvar read. A list of symbols alone therefore needs GENEINFO; calls that neither can place are counted as unplaced, with a gene_annotation_missing warning (or build_unknown when the VCF's build is unknown). A variant ClinVar places in several listed genes is one finding, named after all of them (GENE1/GENE2). The section also counts the P/LP calls outside the list and links the full table of every carried call (clinvar_pathogenic.confidence.tsv). A user's file has no version, citation or URL; those fields are empty strings in the JSON.

The built-in spans are each gene's MANE Select transcript in NCBI's annotation release GCF_000001405.40-RS_2025_08 (GRCh38.p14) and its RefSeq Select transcript in release 105.20220307 (GRCh37.p13); APC's also covers promoter 1B (NM_001127511). One transcript keeps readthrough and alternative models from reaching neighbouring genes (MSH2 into KCNK12, BRCA1 into NBR2). scripts/build_report_gene_lists.py builds the lists, records where they differ from UCSC refGene, and stops on a difference over 25 kb unless the gene is a reviewed exception (recorded in the release's build_info.json).

ACMG reports some genes only in particular cases. For MUTYH, CASQ2, TRDN, BTD, GAA, ATP7B, RPE65 and CYP27A1 only two P/LP variants (biallelic) count, for ABCD1 not a single heterozygous one, and for HFE only p.C282Y homozygotes. TTN counts only truncating variants, RYR1 only malignant-hyperthermia variants, and LMNA not missense variants never seen with cardiac disease. Those findings carry this as a note.

The section also counts each listed gene's P/LP calls by zygosity (heterozygous, homozygous, hemizygous for a haploid genotype, partial for a genotype whose other allele was not called, such as 1/.), with the weakest confidence label of those calls. For a gene the list marks as autosomal recessive (inheritance AR; the built-in lists take it from Table 1) it gives a status:

  • biallelic: a homozygous call; calls of two ALTs of one multi-allelic call such as 1/2 (one on each copy; vcf clinvar keeps the split record in OLD_MULTIALLELIC); or heterozygous calls phased on opposite copies (trans: 0|1 and 1|0) in one phase set;
  • possible biallelic: two or more heterozygous calls whose phase is unknown, so they may be on the same copy (cis) rather than one on each (trans); or a hemizygous or partly called genotype, which doesn't show the other copy;
  • carrier: one heterozygous call, or several phased on the same copy (cis) in one phase set.

Calls are on known copies only when their genotypes are phased (|) and share a phase set: the same chromosome and FORMAT/PS, as WhatsHap, LongPhase (vcf phase) and read-backed callers write it. Unphased calls, calls in different phase sets and pipes without a PS (statistical phasing doesn't say which calls were phased together) leave the phase unknown, as do a triploid or partly called genotype. Each gene's phase is trans when two of its heterozygous calls are on opposite copies, cis when all are on one copy, unknown otherwise, and null with fewer than two; each finding's variant carries its phase_set, and the summary adds (cis) or (trans) when the phase decided the status.

So an HFE p.C282Y homozygote shows as biallelic, two unphased heterozygous ATP7B calls as possible biallelic, and two MUTYH calls phased in one block as carrier (cis) or biallelic (trans). The summary names each status, with the calls' confidence when it is not high. The report does not work out variant consequence or which HFE variant a call is, and X-linked genes get counts but no status. If the run's confidence table is missing, its manifest lists only the first 1,000 calls; the section then warns (calls_truncated) and gives only biallelic statuses, which more calls can't change.

Mitochondrial DNA: heteroplasmy at reviewed variants#

Educational, for review with a clinician; not a prescribing instruction. Confirm any detected variant in an accredited clinical laboratory before acting on it.

This section reads the mutserve calls and per-position read table that lineage mt-haplogroup --contamination keeps for a BAM or CRAM (lineage.md). Without them (no run, a run without --contamination, or a VCF input) the section is not run and names the command. It keeps three things apart:

  • Technical support (technical): mutserve's version and settings, the mtDNA reference the reads were called against (rCRS or CHM13v2.0's chrM, with contig and MD5), median depth, the share of positions with 100 or more reads, the counts of homoplasmies and heteroplasmies, and haplocheck's contamination status.
  • Reviewed disease variants (group disease): the mtDNA SNVs that ClinVar classifies Pathogenic with expert-panel review (ClinGen's Mitochondrial Disease Variant Curation Expert Panel) and no conflicting classifications.
  • MT-RNR1 aminoglycoside-risk alleles (group aminoglycoside): m.1095T>C, m.1494C>T and m.1555A>G, which CPIC classes as "increased risk of aminoglycoside-induced hearing loss" (McDermott et al., Clin Pharmacol Ther 2022;111(2):366-372, PMID 34032273), with ClinVar's record for each. CPIC found no heteroplasmy level at which aminoglycosides become safe and treats a detected variant at any level like a homoplasmic one, so a supported heteroplasmic call is reported as risk evidence; it does not need 100% ALT reads.

The reviewed variants are src/wgsextract_cli/assets/report/mt_variants.json, bundled with the package (the report makes no network request). scripts/build_report_mt_variants.py rebuilds it by that rule from a pinned ClinVar GRCh38 VCF release (2026-11-15; its URL, fileDate and NCBI MD5 are recorded, with each variant's Variation ID, classification, review status and conditions) and CPIC's Table 1. MITOMAP is not used. ClinVar's data carry no NCBI use restrictions; CPIC's content is CC0 1.0 (see NOTICE). The section's resource repeats the release, MD5, selection rule and citation.

Each reviewed variant gets one state (sites), from the evidence at its rCRS position (a CHM13 run's evidence is read at the matching CHM13 position):

StateMeaning
homoplasmicmutserve called the ALT at 95% or more
heteroplasmicmutserve called it at 10% to 95%
weak_evidencea call below 10%, or ALT reads at 1% or more on a strand that mutserve didn't call (strand_bias when only one strand carries them, mt_not_called otherwise)
not_detected100 or more reads, none (under 1% on each strand) with the ALT
not_assessedfewer than 100 reads, no reads, an unconfirmed reference, a reference base or call that disagrees with the read table, or missing evidence (see reasons)

The thresholds follow gnomAD's mtDNA release (Laricchia et al., Genome Res 2022;32:569-582, PMID 35074858): it reports heteroplasmy from 10%, calls 95-100% homoplasmic, and treats a site without a call as reference only above 100x. In their dataset, the authors estimated that misaligned nuclear copies of mtDNA (NUMTs) accounted for at least 43% of 1-5% calls and 1% of 5-10% calls. Those estimates are not universal error rates, and this report retains lower calls as weak evidence. With 100 reads, a 10% heteroplasmy leaves no ALT read with probability 0.9^100 (under 3 in 100,000), so not detected rules out heteroplasmy of 10% or more, not lower levels. 1% is the level mutserve calls from in this run. These are technical limits: levels are measured in the sequenced sample (usually blood) and can differ in other tissues and over time, and NUMTs, contamination and low mtDNA copy number can all imitate low-level heteroplasmy. Not assessed is unknown, never a negative. The section warns mt_reference_unconfirmed (no variant assessed) when the run's mtDNA reference wasn't confirmed as the rCRS or CHM13v2.0's chrM, and mt_evidence_missing when a kept file is missing or unreadable.

Detected and weak-evidence variants are findings. Their variant gives the level as alt_fraction and homoplasmic or heteroplasmic as zygosity, with no genotype: a mixture is not a diploid genotype. clinical_evidence holds the ClinVar Variation ID and review status; the region is the position in the evidence file. A finding's note gives the clinician-review context.

Automated ACMG classes (research only)#

Research use only; not a diagnosis. These classes are computed automatically by fastVEP from public databases, without the clinical, family and functional evidence a classification needs, and a VUS can mean that nothing was checked.

This section appears only when vcf acmg ran for the sample. It is opt-in research: a report without it never asks for it. The disclaimer heads the section, and each of its findings carries "Research use only; not a diagnosis." instead of the technical-result disclaimer.

The report reads acmg_annotated.vcf.gz itself (about a second per chromosome 22, a minute or so for a whole genome). It counts the classes (P, LP, VUS, LB, B) of the alleles the sample carries (every ALT of a sites-only VCF) and lists each carried P/LP call in a gene of the gene list (the same list and reporting notes as the ClinVar section), placed by the VEP gene symbol of the transcript the variant table shows, or by the list's spans when there is none. A finding gives the class, the criteria fastVEP found met, the transcript it classified on, the HGVS change and consequence, and the call's sequencing confidence (variant-confidence.md; not_assessed for a sites-only VCF). P/LP calls outside the list are only counted; every class is in the classified VCF and in its variant table. The JSON section adds disclaimer, gene_list, tool, criteria_not_evaluated (criteria fastVEP never evaluates, such as PS3/BS3), build, counts and all_calls.

As in the ClinVar section, an imputed P/LP allele rarer than 1% in the panel (or of unknown panel frequency) is counted but not listed (rare_imputed_not_listed), and a sample that qc contamination found contaminated has every call at most moderate (sample_contaminated). A multi-sample VCF is read for its first sample, named in a confidence_first_sample_only warning; subset it to the intended sample first. A classified VCF that can't be read (unreadable_evidence) leaves the section without findings; the rest of the report is still written.

Confidence labels#

Every finding has a label, high, moderate, low or not_assessed, with reason codes. The JSON document explains each code in confidence_reasons.

  • ClinVar: the call's own label from vcf clinvar (variant-confidence.md): depth, genotype quality, allele balance, mapping quality and strand bias.
  • PharmCAT: the weakest label among the gene's labelled calls in the run's confidence table. A gene with no labelled calls (a reference *1/*1 rests on coverage alone) is not_assessed, and so is a gene judged only from a manifest that lists some of the calls (calls_truncated, when the confidence table is missing).
  • HLA-A and HLA-B (T1K): low when typing hla made no confident call; high when T1K's quality is above 0 for each allele (its own threshold) and the names it tied agree; moderate when the T1K genotypes file is missing; not_assessed (with an evidence_mismatch warning) when the file no longer gives the call the run recorded. The detail gives the qualities and the IPD-IMGT/HLA release.
  • CYP2D6 (Cyrius): low when Cyrius made no call, its filter did not pass, or its variants fit more than one diplotype (genotype_unresolved: the value reads "unresolved" and the detail lists Cyrius's candidates); moderate at best for runs that predate recording Cyrius's Call_info; otherwise the median depth against the confidence_min_depth and confidence_high_depth settings (low below the minimum, moderate below the high threshold, high above it).
  • SMA carrier status (SMNCopyNumberCaller): low when there is no SMN1 call (including below 30x, where typing smn withholds calls), the carrier/affected status is uncertain, the caller's filter isn't PASS, the input's aligner isn't bwa-like (aligner_not_calibrated), or coverage is uneven (MAD above 0.11); moderate when the depth is unknown; otherwise high.
  • Mitochondrial heteroplasmy: high for a homoplasmic or heteroplasmic call, or a supported negative, at 100 or more reads; low for weak evidence or under 100 reads (mt_low_depth). Haplocheck contamination makes a heteroplasmic call low and a homoplasmic one moderate (mt_contamination); qc contamination makes either at most moderate (sample_contaminated). See above.
  • Haplogroups: the caller's quality score (Yleaf QC-score, Haplogrep 3 quality): high from 0.9, moderate from 0.7, low below 0.7. A run that warned of low coverage is low.

Evidence and privacy#

Each finding names its evidence: a file, relative to the sample folder (the ClinVar VCF, the haplogroup report, the PharmCAT report, the Cyrius and SMNCopyNumberCaller calls, the T1K genotypes), the region (chrom:pos, the chromosome, or gene SYMBOL), and the run's result manifest. In the HTML and Markdown these are links, relative to the report's folder, so the report keeps working when the sample folder is moved or copied as a whole. When the folder has been moved or copied, the report uses the files in its own folder rather than the paths the manifests recorded. Evidence on another drive (--results on Windows) has no relative path, so it is named, and linked, by its absolute path.

The documents name the sample folder but not its full path, so the report can be shared without the folder layout of your computer. Paths in the runs' warnings and errors are made relative to the sample folder, or cut to the file name when outside it. They do contain the sample's findings: treat them as private genetic data.

The HTML is self-contained: inline CSS, no scripts, fonts, images or other remote resources, and no-referrer on its links. It renders offline in any browser on macOS, Linux and Windows. Rendering makes no network calls; the only remote addresses are the haplogroup tree links, which open only when you click them.

JSON document#

<sample>_personal_report.json follows the wgsextract.report/1 schema (src/wgsextract_cli/assets/schemas/wgsextract.report.1.schema.json). The same document is the details of the report's result manifest (<sample>_personal_report.manifest.json), of --json output and of api.report.build().

The committed schema is regenerated with scripts/gen_report_schema.py (--check detects drift), also included in just regen. Source-run, newest-attempt, warning, missing-command, external-link, finding, evidence, variant, pharmacogenomics, fact and QC components come from the writer-used types in core/report_documents.py and core/clinical_evidence.py; their HTML and Markdown renderers use the same types. The sample, section map, section-specific records and root also come from writer-used Python types: no handwritten structural schema template remains. This does not add runtime validation or change how old reports render. The HTML, Markdown and findings-table consumers use those document types too; the complete raw TypeScript contract is generated into gui/app/shared/generated/report-records.ts by scripts/gen_server_contracts.py.

Every section has title, status (ok, not_run or failed), summary, findings, missing (what and the command to run in the sample folder), warnings, sources and, when failed, error. Each source gives the selected run's command, status, finished and manifest, and latest_attempt: null when it is the newest run of its step, otherwise the newer failed or cancelled attempt with the same four fields. The overview adds facts and qc, ClinVar adds gene_list, build, counts, genes and all_calls, exon callability adds gene_list, build, exon_model, scope, thresholds, counts, genes (each with its state, result and result_text), all_exons, evidence, unassessed_variant_classes and note, the mitochondrial section adds advisory, technical, thresholds, resource, sites and counts, and the microarray section adds files and metrics.

The findings table has one row per finding, with the variant's columns, the label and its reasons, the evidence file and region, and the disclaimer. Its columns are described in the Parquet footer like the other tables (parquet.md).

The report's result manifest records the source manifests as inputs (role manifest), the resource releases its sections rest on (resources: the source runs' ClinVar release and the gene list; see recheck-and-delta.md, which also covers ref recheck and comparing two reports with report-delta), the four documents as outputs (report_html, report_markdown, report_json, findings_table), the metrics findings, findings_<label> and section_<name> (each section's status), and a section_failed warning for each failed section and a newer_attempt_failed warning (with its section) for each source that a newer failed attempt followed.

Implementation layout#

The internal core/personal_report/ package keeps the existing import interface. Its initializer assembles the JSON document and findings table, re-exporting existing helper paths. context.py collects manifests and workspace evidence and provides shared finding/confidence support. overview.py builds sample, lineage, ancestry and microarray summaries; genotyping.py builds PGx and carrier sections; clinical.py handles ClinVar and per-gene call interpretation; callability.py reads vcf callability and combines it with the ClinVar section; callability_rendering.py formats the exon-by-gene table and evidence links; mitochondrial.py reads mtDNA heteroplasmy evidence through core/mt_heteroplasmy.py; variant_sections.py handles automated ACMG and structural-variant evidence. rendering.py formats the offline HTML/Markdown documents and evidence links. Confidence and clinical rules remain independent of presentation.
