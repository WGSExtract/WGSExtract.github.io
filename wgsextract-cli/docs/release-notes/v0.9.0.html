WGS Extract 0.9.0

You can annotate GRCh38 variants offline with SCREEN cCREs and GTEx v10 SuSiE eQTL matches, and export gnomAD FAF95, protein residue positions and domain overlaps. Research panels can weight small variants and compare combined small-variant and whole-gene CNV burden against matched controls. For long reads, bonefish is an experimental alignment option. New calls from bcftools 1.25 preserve fractional mapping quality.

Command help and run manifests now show certification levels. Low Data Mode requires approval for large downloads, and the desktop app asks before going online on first launch. The desktop app can reuse results already on disk, and you can search the Tools, Reference Data and Reference Genomes lists.

Changed#

  • info gene help explains that the optional gene.iobio hand-off is desktop-only and states its licence and non-clinical-use terms. The CLI stays offline (#1113, gene.iobio integration).
  • With GATK 4.6.2.0, selecting whole contigs from an indexed CRAM 3.0 no longer writes a temporary BAM when the CRAI is compatible. Partial intervals and unqualified readers keep the existing staging path (#1125, streaming disposable intermediates).
  • vcf impute releases temporary Beagle genotype and imputation files after their last use instead of keeping them for the entire run (#1125, disposable genome handoffs).
  • vcf impute releases a chromosome's GLIMPSE2 chunk files after successful ligation instead of keeping them until the full run ends, reducing peak temporary disk use (#1125, disposable genome handoffs).
  • Chunked ONT and PacBio realignment can write sorted reads directly to its restartable reference groups, without a temporary BAM and index for every chunk (#1125, streaming disposable intermediates).
  • Paired short-read realignment with minimap2 can stream newly extracted reads instead of writing intermediate FASTQs. Existing FASTQs, --keep-fastq, and the low-memory file fallback are unchanged (#1125, streaming disposable intermediates).
  • typing target-cnv and vcf callability now share specialist caller recommendations for known short-read limitations. For example, masked PMS2 regions point to long-read typing paraphase without being reported as callable (#1285, paralog typing and target copy number).
  • Stale-worktree cleanup can accept explicitly named ignored build outputs without discarding tracked edits, and saves small last-run records with the other archived evidence.
  • cohort summarize flags small or sparse allele counts and warns when available relatedness results suggest relatives. The optional local --export omits flagged rows and excludes exact genotype breakdowns and participant identifiers.
  • ref acmg-data stays offline unless you pass --download. An offline --dry-run still lists the sources and their terms.
  • wgsextract --version and wgsextract --help skip imports for run logging, worker pools, and result schemas when those features are not used. They still validate config and check for workspace moves (#1506, CLI startup).
  • The CLI and the desktop app’s direct CLI launcher start faster by loading settings and resource helpers only when needed. Local info no longer loads the download stack. Config validation and workspace move checks still run (#1506, CLI startup).
  • wgsextract --version and --help start faster by loading configuration without initializing the command runtime. Configuration is still validated.
  • wgsextract --version answers without building the command parser, while still checking the workspace and configuration.
  • wgsextract --version starts faster on Windows, including when launched directly by the desktop app. It still validates the configuration and respects workspace moves.
  • vcf acmg uses a local indexed sweep for densely spaced sites. Sparse and remote lookups still use the range reader.
  • vcf gnomad builds its normalized allele lookup in fewer passes on a cache miss, without changing how alleles are matched.
  • Compact CLI discovery (wgsextract help --all --json) now uses a bundled build artifact or a writable cache. If the index is missing or outdated, discovery rebuilds it locally without modifying the installation.
  • The command, Python API and configuration references are generated when the documentation site is published.
  • New calls from bcftools 1.25 on Linux, macOS, and Windows x64 store average mapping quality (INFO/MQ) as a Float instead of an Integer. Filters that use MQ can select different records because they now see the fractional part (#1555, bcftools 1.25 qualification).
  • On macOS, Delly now uses a separate environment. Install it with pixi install --locked -e delly before using vcf sv or vcf cnv with Delly.
  • The default output folder beside a lab's BAM, CRAM, FASTQ, VCF or microarray file is now WGSEv6/ (was wgse/). Inputs already inside an older wgse/ folder keep writing there, so existing file sets don't get a nested folder (#1581).
  • Run manifests (*.manifest.json) and info caches (*.wgse_info.json) now go in a manifests/ subfolder of the output folder, and never in the lab's own folder: bam index still writes its .bai beside the BAM, but its manifest goes to WGSEv6/manifests/. info without --outdir caches its results there too, instead of beside the input. Manifests and caches that earlier releases wrote beside files or in wgse/ are still read (#1581).
  • Desktop settings now keep the launch update check separate from Privacy mode. Upgrades that already completed setup retain their previous effective update behavior (#1591, network principles).
  • vcf variantqc is now certified Validated: real DISCVRSeq 1.3.86 on Java 17 matched bcftools counts for HG002 GRCh38 calls on Windows (#1621, VariantQC and Tools labels).
  • just certify-setup --reference prepares one checksum-verified reference library per host. New worktrees can link it offline with --link-reference instead of retaining another copy.
  • deps list, deps install and the desktop app say why a tool isn't available on this computer, not just that it isn't built for it: for example, that granite loads pysam and pytabix, which have no Windows builds. Platforms are named as people say them ("Windows", "macOS on Apple silicon", "Linux ARM64"), never "win32" (#1657, Tools page follow-ups).

New#

  • align and realign accept --output-profile fast to write lossless CRAM 3.1 faster at the cost of larger files. In staged alignment it also uses level-1 compression for the internal raw BAM and budgets more disk space for it. Defaults and duplicate marking are unchanged (#1130, alignment compression timings).
  • vcf callability classifies each coding exon of a gene list (ACMG SF by default; MANE Select on hg38, RefSeq Select on hg19, bundled) from the sample's gVCF as callable, partial, not readable, specialist required (a GIAB low-mappability or segmental-duplication region) or not run, so a gene with reads over 90% of its body no longer hides an unread exon. The report's new exon callability section says, per gene, whether the ClinVar section's silence means not reported, not readable or not run. Callability is technical: it never establishes the absence of disease. Works offline (#1177, exon callability).
  • extract ydna-vcf --ybrowse (and extract region --target y --ybrowse) now works on GRCh37 alignments, with the same yBrowse IDs and HG/ISOGG/AA annotations as on GRCh38. Run ref ybrowse --install --grch37 --download once: it lifts the installed GRCh38 yBrowse snapshot to GRCh37 with Ensembl's pinned GRCh38->GRCh37 chain (fetched only with --download; or give one with --chain) and checks every allele against your GRCh37 FASTA. Sites the chain can't place exactly once, or whose alleles don't match GRCh37, are dropped and counted in the VCF header. YBrowse's own GRCh37 file isn't used: its positions are GRCh38's. T2T stays unsupported (#1186, GRCh37 targeted Y VCF).
  • vcf table exports in-silico scores as typed columns: revel, alphamissense_score and alphamissense_class, cadd_raw and cadd_phred, spliceai_max (the highest SpliceAI delta score of the ALT, for the row's gene), phylop, gerp, and SIFT's and PolyPhen's scores and predictions. They come from vcf revel, vcf alphamissense, vcf cadd, vcf spliceai, vcf phylop and vcf gerp, else from fastVEP's and VEP's own fields (plugins, dbNSFP, SIFT and PolyPhen). An unscored variant leaves them empty, never 0. The server's /v1/variants and MCP query_variants return them too (#1284, vcf table in-silico score columns).
  • panel audit can compare a research gene group's qualifying allele copies with coding-length-matched groups in the same genome. Its GRCh38 MANE exon model is only fetched with --download, and gVCF callability is reported separately from the model-length fallback. For XY samples, matching separates diploid and haploid X regions and counts a homozygous ALT call in a haploid region as one copy.
  • panel audit --research-panel applies a research panel to a local, annotated single-sample VCF. It lists qualifying and unscored alleles, distinguishes reference evidence from unassessed sites, and reports phase and named haplotype patterns when the genotypes support them.
  • report includes a separate research-only summary of the sample's panel audit when it finds the audit manifest, with links to the local evidence.
  • vcf compare reports local small-allele and genotype agreement across callsets, or selects shared family alleles with optional strict gVCF exclusions and BED scoping. It can also write an indexed single-sample VCF annotated with each callset's state (#1295, local VCF concordance).
  • Run lineage follow-ups: analyze comprehensive now refuses a VCF filtered or annotated from wgsextract's calls of another person's reads, not only the calls themselves; each VCF's artifact names the reads it was called from in called_from. vcf chain-annotate lists its annotators' runs in run.children, and a step interrupted by cancelling analyze is listed as cancelled. A server job's steps read manifests and indexes only in the server's folders, a crafted index with negative counts is refused, and a pipe named like a manifest no longer blocks a run (#1379, run lineage pilot follow-ups).
  • panel audit --gnomad-expected can compare its CDS-only null with a null also matched on gnomAD v4.1 expected synonymous counts, using the same genes and filters. The pinned CC0 reference is downloaded only with --download.
  • fastq archive and fastq restore compress and verify one or two FASTQ files offline, preserving the exact FASTQ bytes and read order without replacing the originals (#1432, open FASTQ compression).
  • Research-only vcf acmg uses RepeatMasker for BP3 and gnomAD region flags to withhold population evidence at flagged sites under fastVEP's default rule. This can shift benign calls to VUS: 8,669 alleles (17.0%) did so on HG002 chr22, with no new pathogenic or likely pathogenic calls. The VCF marks calls at flagged positions and the run report identifies evidence that couldn't be evaluated (#1458, ACMG region tracks).
  • vcf chain-annotate --dry-run prints the plan and records details.steps and details.dry_run in a separate plan manifest without changing the annotation outputs or resume journal.
  • wgsextract ref needs now inspects info gene invocations and reports a missing CRAM reference genome or RefSeq gene-map table (without flagging missing VCF annotations) (#1550, GUI UX, user docs, and rendered HTML docs).
  • Repository Markdown documentation (README.md, docs/, gui/docs/, and gui/devdocs/) is rendered to static HTML with GitHub-compatible heading anchors and published under wgsextract-cli/ and wgsextract-cli/app/, with https://wgse.bio/wgsextract-cli/... links in CLI download/recheck errors and HTML personal reports (#1550, GUI UX, user docs, and rendered HTML docs).
  • vcf compare --atomize compares primitive alleles against a local reference, so an MNP can match separate SNVs. For two-callset concordance, --emit-partition-vcfs writes indexed shared and one-sided allele VCFs. Neither option changes the default comparison (#1582, VCF atomization and partitions).
  • methylation regions --preset imprinted-dmrs --build hg38 summarizes 14 imprinted regions from pooled CpG calls or haplotagged alignments. The bundled panel works offline and is for research, not clinical interpretation (#1583, imprinted DMR preset).
  • Set network_mode in config.toml or pass --network full|low|off for one run. Low mode requires --allow-large-download for bulk transfers; off mode blocks network operations even when a download was requested. Existing download and disclosure opt-ins still apply.
  • CLI help, API discovery and MCP tool descriptions show each command's certification level. Detailed help and the published certification reference link to the evidence. Result manifests record the level at run time. Set certification_notices = false in config.toml to hide Tested and Experimental notices (#1596, command certification).
  • Research panel audit supports optional small-variant weights, predictor fallback, genotype dosage and an allele-matched ClinVar benign veto. Matched controls use the same scoring rules. Existing panels keep their copy counts.
  • deps list marks each optional tool that ships in the CLI's own environment as preinstalled: it comes with WGS Extract and can't be uninstalled on its own (#1621, VariantQC and Tools labels).
  • vcf table exports protein residue starts and ends and reported domain overlaps for the selected allele and transcript. It reads existing VEP or SnpEff annotations without downloading reference data. The columns are also available through the variants API and MCP lookup (#1622, protein positions and domains).
  • New gnomAD v4.1 tables retain ancestry-group maximum FAF95. vcf gnomad annotates it and vcf table exports it as gnomad_faf95. Existing tables still work; to add FAF95, run wgsextract ref gnomad --release 4.1 --download (about 900 GB). AF filters and ACMG defaults are unchanged (#1623, gnomAD FAF95).
  • Opt in to offline GRCh38 SCREEN cCRE overlap with vcf regulatory or vcf chain-annotate --annotations regulatory. Install the pinned track explicitly with ref regulatory --download. VCFs gain per-ALT class and accession annotations, and vcf table exposes ccre_class for research use (#1624, regulatory tracks).
  • align and realign accept the experimental CPU --aligner bonefish for ONT DNA and PacBio HiFi. Install bonefish 0.5.2 or newer separately. The default aligner selection is unchanged.
  • deps list rows list used_by, the commands whose runs need or may use each tool (#1657, Tools page follow-ups).
  • deps list reports the computer in details["host"]: OS and version, architecture, CPU cores and threads, memory, and free space on each disk holding WGS Extract's folders (#1657, Tools page follow-ups).
  • PLINK 2, used by score pgs --plink2-check, now installs with wgsextract deps install plink2 (the Tools page's Install button) instead of by hand: from Bioconda into its own Pixi environment on Linux and macOS, and on Windows x64 from the author's official build, pinned by version and SHA-256. deps uninstall plink2 removes it (#1658, install PLINK 2 and Dorado).
  • Dorado 2.2.0, used by basecall, now installs with wgsextract deps install dorado --accept-license on Linux x64 and ARM64, Apple silicon Macs and Windows x64: ONT's official release, pinned by SHA-256. Dorado is licensed under the Oxford Nanopore Technologies PLC. Public License Version 2.0, for research use only; install shows the licence and downloads nothing until you accept it. deps uninstall dorado removes it (#1658).
  • Opt in to offline GRCh38 GTEx v10 SuSiE eQTL matches with vcf gtex or vcf chain-annotate --annotations gtex. Install the pinned public track explicitly with ref gtex --download. The TSV preserves each exact ALT, gene, tissue, credible set, PIP and reported aFC (#1662, GTEx eQTL annotation).
  • Research panel audit can combine small-variant burden with local whole-gene deletion and duplication calls, and compares it against coverage-, GC- and mappability-matched controls when eligible (#1664, matched panel CNV calibration).

Fixes#

  • Documented upstream licences, attribution and unresolved terms for reference data, vendor templates, model weights and other third-party resources. The notices distinguish noncommercial and academic-only terms from unknown grants; downloads, bundled files and the BMI score selection are unchanged. (#864, resource rights records)
  • vcf impute now explains how to rebuild cached GLIMPSE2 references without downloading the panel again after switching GLIMPSE2 builds.
  • When vcf clair3, vcf gatk, or vcf deepvariant --gpu requests a gVCF, the callset and its indexes are published together. A failed gVCF step leaves any previous callset intact (#1125, streaming caller intermediates).
  • Reference-normalized annotation no longer writes a full text VCF copy of ClinVar, gnomAD, CADD indel, or other whole-resource inputs to scratch. The first run streams normalization and still matches against the compressed, indexed resource.
  • panel audit accepts DeepVariant gVCFs with <*> reference blocks even when the caller omits their ALT header declaration.
  • vcf compare no longer treats a companion gVCF reference block as proof of absence when a primary ALT, filtered record, or no-call overlaps the assessed span (#1295, VCF comparison).
  • Worktree cleanup can remove explicitly approved ignored build files from a retained checkout while preserving its source, evidence, and linked files (#1393, safe stale-worktree cleanup).
  • vcf chain-annotate rejects repeated annotators and unknown or out-of-bounds --region values. It clips BED intervals to known contig lengths and warns with bed_contigs_not_in_vcf for omitted contigs and no_variants for a header-only result. The manifest reports region_intervals and region_bases for the merged scope in metrics and provenance.params (region_bases is null for open-ended regions on contigs of unknown length). For BED selection, provenance.params records bed and bed_sha256; the digest is also in details.scope. (#1475, chain annotation validation and reporting)
  • Sex inference works again on short-read low-pass genomes below 3x, such as 2X consumer CRAMs and downsampled subsets, which had been reported as Unknown so that microarray, variant calling and other sex-aware commands refused them. Reads are counted in more indexed windows, so a CRAM is still not read whole (#1578, low-pass sex inference).
  • info reports a single-end library's insert size as its read length instead of 0 bp, and refreshes caches that stored 0 bp (#1581).
  • ref microarray-targets now names any missing liftOver chain and asks for --download instead of fetching it automatically.
  • DeepVariant and Parabricks no longer let Docker fetch an image that disappears between the dependency check and launch. Install missing images separately with docker pull.
  • The interactive reference library resumes an interrupted download only when you choose Resume; pressing Enter cancels.
  • Pinned BGZF reference downloads, including the 1000 Genomes imputation panel, now retry damaged byte ranges instead of discarding the whole download. The file is installed only if its SHA-256 matches the pin (#1619, corrupt imputation panel downloads).
  • vcf variantqc gives DISCVRSeq the <vcf>.tbi index it needs: it indexes an unindexed .vcf.gz beside itself, or works from an indexed copy when the VCF is plain text, has only a CSI or sample.vcf.tbi index, or is in a read-only folder. DISCVRSeq stopped with "An index is required but was not found" in those cases (#1621, VariantQC and Tools labels).
  • vcf call writes uppercase REF and ALT sequences even on soft-masked references. Panel watches, ACMG annotations, variant tables and polygenic scores now match lowercase sequence alleles in input VCFs, and qc relate accepts lowercase alleles in custom sites files (#1630, lowercase VCF alleles).
  • Cancelling a stalled ref gnomad download on Windows no longer waits for shutdown grace periods intended for Unix processes (#1643, slow gnomAD cancellation).
  • Clair3, DeepVariant, GATK, FreeBayes, and structural variant callers now write uppercase sequence alleles on soft-masked references. Symbolic alleles, breakend contig names, and gVCF reference block boundaries are preserved (#1654, lowercase caller alleles). Rerunning a completed DeepVariant job from an older version regenerates its outputs once.

Desktop app#

Added#

  • Open an hg19 or hg38 Gene page result in gene.iobio after reviewing its licence and confirming each launch. The hand-off sends the gene symbol and reference build, not sample files or IDs (#1113, gene.iobio integration).
  • Privacy mode under Settings → Network & Privacy pauses the app's automatic network activity. While it is on, a red PRIVACY badge shows under the app's name; its tooltip says where to turn it off (#1548).
  • Gene page now checks required reference files (CRAM reference genome and RefSeq Gene Maps, excluding missing VCF annotations) before running and offers Cancel, Continue, or Install and Continue, with a dedicated sidebar icon (#1550, GUI UX, user docs, and rendered HTML docs).
  • Commands with fresh permanent outputs on disk now reuse them directly: result cards open immediately with a Force Run Again button, HTML reports open directly, and output-only commands prompt Cancel vs. Force Run Again (passing --force or --restart where supported) (#1550, GUI UX, user docs, and rendered HTML docs).
  • Separated desktop end-user documentation (gui/docs/) from developer documentation (gui/devdocs/), added user guides for Basic/Advanced mode, Reference Data, Reference Genomes, Tools, Settings, and Desktop Privacy, and documented the CLI-vs-GUI privacy and network boundary (#1550, GUI UX, user docs, and rendered HTML docs).
  • Inline errors, result notices, result summaries, and terminal output now turn https://wgse.bio/... URLs and repository doc references into clickable browser links (#1550, GUI UX, user docs, and rendered HTML docs).
  • On first launch, WGS Extract asks before going online. Choose OK to continue setup and enable update checks at launch, or Not now to stay offline and open Settings → Network & Privacy (#1591, network principles).
  • Network & Privacy settings show whether the OS reports a metered or constrained connection. Automatic mode uses Low on those connections and asks before setup downloads. You can also choose Full, Low, or Off.
  • Basic and Advanced tools show the CLI’s certification level. Hover over or focus a badge to see what the level means, or select it to see the command’s evidence.
  • Tools, Reference Data and Reference Genomes each have a keyword filter on their title line. Typed words match a row's name, tags, status or shown columns, such as a build on Reference Genomes (#1628, library sort and filter).
  • The Tools page shows the computer the CLI runs on: operating system and version, architecture, CPU cores and threads, memory, and free disk space where WGS Extract keeps its files (#1657, Tools page follow-ups).
  • The Tools page has a "Hide mandatory and pre-installed" checkbox beside its filter, checked by default. A mandatory or pre-installed tool that is missing stays in the list (#1657, Tools page follow-ups).
  • The Tools page installs Dorado. Its Install button first shows Dorado's licence, the Oxford Nanopore Technologies PLC. Public License Version 2.0 (research use only), and installs only when you choose Accept and install. PLINK 2 now has an Install button too (#1658).

Changed#

  • The gene.iobio consent dialog now lists the local files used for the current gene result and which indexes to select on the website. The browser link still sends only the gene and reference build (#1113, gene.iobio integration).
  • After Setup, the desktop app launches the installed CLI without starting Pixi for every call. Older runtimes and explicit Pixi overrides retain the offline Pixi launcher (#1506, CLI startup).
  • The desktop app starts its installed CLI without loading the subprocess fallback unless the cached activation fails.
  • When Check for updates at launch is enabled and Privacy mode is off, the desktop app offers newer releases in the sidebar. A failed startup check shows nothing. File → Check for Updates… still checks on request.
  • Running the app from a source checkout (make run, make tauri, npm run dev) keeps its own data folder, WGSExtract-gui-dev, so it no longer replaces the installed app's copy of the bundle or its CLI runtime. It also keeps its own users workspace, ~/wgs-extract-dev.
  • Removed the inline View reads button below BAM/CRAM selectors and removed the redundant Reference Genome dropdown from the Microarray page (automatically detected from the BAM/CRAM) (#1550, GUI UX, user docs, and rendered HTML docs).
  • Removed the angled "AI written" corner banner from both documentation sites (#1550, GUI UX, user docs, and rendered HTML docs).
  • In Basic mode, the BAM page's Sort and Index buttons stay visible but are disabled, with a tooltip saying why, when the file is already coordinate sorted or indexed. Sorted is now read from the file's header (SO:coordinate) rather than guessed from its name, and the status refreshes after a command finishes or the mode changes.
  • Outputs go to a WGSEv6/ folder beside the input, with manifests in WGSEv6/manifests/; existing wgse/ folders keep being used.
  • Desktop pages and tools use genomics icons for file formats and analysis tasks. Standard controls and Emoji mode keep their existing icons.
  • The Tools page labels optional tools that ship with WGS Extract, such as fastp, FastQC, samblaster and minimap2, "pre-installed" instead of "optional", since they can't be removed on their own (#1621, VariantQC and Tools labels).
  • The Tools page no longer shows a certification badge beside each tool's Install, Uninstall or check button. The badge was the rating of the dependency manager, not the tool, so Java 17 and DISCVRSeq appeared Experimental (#1621, VariantQC and Tools labels).
  • The Tools page lists installed tools first (mandatory, then pre-installed, then the rest), then missing tools, then tools not available on this platform. Reference Data lists installed resources before missing ones. Each group is alphabetical (#1628, library sort and filter).
  • In Basic mode the Tools page leaves out tools that only Advanced features use (#1657, Tools page follow-ups).
  • Tools, Reference Data and Reference Genomes come back at once when you return to them: their lists are kept until an install, download, uninstall or other change that affects them, or until the app restarts (#1657, Tools page follow-ups).
  • A "not available" tool's row says why it can't be had on this computer. A tool's tooltip no longer repeats the row's note (#1657, Tools page follow-ups).

Fixed#

  • Reference Data shows the installed bootstrap version, current download size, and an update badge for older installations. The reference path shows the actual folder, and the Gene page sidebar label stays on one line beside its icon.
  • Switching between Basic and Advanced always redraws the page, even when saving the choice fails (#1657, Tools page follow-ups).
  • Setup can initialize the reference library with the older v0.8.10 CLI, which predates the new network-mode options. Local commands still run in Low Data and Off modes; the bundled CLI uses its own download consent (#1674, bundled CLI setup).
  • After a desktop app upgrade, Setup now offers to install the CLI version required by the app. On Windows, a failed CLI upgrade restores the previous installation. Your workspace and settings stay in place.
