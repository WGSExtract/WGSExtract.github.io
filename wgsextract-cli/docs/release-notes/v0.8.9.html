WGS Extract 0.8.9

This release adds a built-in genome viewer to the desktop app, shareable result cards, a Tools page that installs missing optional tools, and CombinedKit v5 microarray templates. Coverage breadth now leaves out reference N gaps. Native DeepVariant handles haploid sex chromosomes and runs faster on Apple Silicon, and GATK and Clair3 gain opt-in Apple Silicon acceleration.

Changed#

  • Coverage breadth leaves out reference N bases. info calculate-coverage and info coverage-sample divided breadth by the full contig length, so the reference's N gaps counted as uncovered: on a 30x GRCh38 genome chr1 read 92.5 % and chrY 41.3 %, now 99.9 % and 99.97 %. The N counts come from the reference's _ncnt.csv, else built-in counts for the standard assemblies; partial regions keep every position. info calculate-coverage --with-bins (the app's Detailed Coverage) prints the v4-style Bin Coverage by Sequence Name table with an N Len column, subtracting Ns once (v4 subtracted them twice) (#1203).
  • Annotation data that ref commands download (ClinVar, CADD, gnomAD, PhyloP, GERP, gene maps, PharmGKB, SpliceAI, ACMG data, the HLA index) now goes in the reference library's downloads/ folder instead of ref/. Libraries that already have data in ref/ keep working without moving it, and ref bootstrap removes the empty ref/ its archive leaves behind.
  • A mitochondrial reference is identified as rCRS or CHM13 by its sequence (M5/MD5, else the indexed FASTA), not by its 16,569-base length; length alone now leaves it unknown (#1194).

New#

  • Result cards. --card (config result_card, off by default) writes a shareable <name>.card.html beside the run's manifest: the command, status, printed result, metrics, warnings and outputs, with the WGS Extract and tool versions, the input file's name, size and short fingerprint, the reference and the run time. Files appear by name only and home paths as ~, so a card can be shared; the manifest keeps full paths (#1143).
  • deps list reports every mandatory and optional tool, whether it is installed, its version and the Pixi environment that provides it, without failing on a missing tool. deps install TOOL and deps uninstall TOOL install or remove the Pixi environment of an optional tool packaged in one (#1191).
  • Microarray CombinedKit v5 adds letter-named vendor variants: AncestryDNA ancestry_v2ab, ancestry_v2cd and ancestry_v2e; FamilyTreeDNA ftdna_v4 and the GRCh38 Y files ftdna_v2y, ftdna_v3y and ftdna_v4y; myheritage_v3; and tellmegen, genera, mthfr, meudna_v1, meudna_v2 and selfdecode (#1107). CHM13v2 input now covers all of them instead of writing no-calls for the v5 additions (#1108).
  • ref cytobands --build hg19|hg38 --download installs pinned, checksummed UCSC cytoband tables for the genome viewer (#1153).
  • serve --listen ADDRESS[:PORT] (opt-in; loopback stays the default) serves the job API beyond this computer. A non-loopback bind requires bearer authentication, a server.public_url (--public-url) and its authority in server.allowed_hosts. The listener speaks plain HTTP: put it behind a TLS reverse proxy or a trusted encrypted tunnel so tokens and genomic data stay protected. Authenticated file range reads for the viewer are off by default, stay inside the guard roots, and need a Linux or macOS host. See the server guide (#1173).
  • vcf gatk --pair-hmm-neon JAR (opt-in, Apple Silicon) runs GATK HaplotypeCaller's PairHMM with GKL's NEON kernels in double precision instead of GATK's Java fallback: about 9x faster over five HG002 chr20 windows, with identical sites, alleles, GT and FILTER. A few reads near the informative cutoff are counted differently in difficult regions (9 of 306,024 reference blocks, 8 final records), so it is not the default. Build the sidecar jar as packaging/arm64/gkl/README.md describes (#1117).
  • Native wgse-deepvariant 0.4.1 optimizes Apple Silicon small-model CPU work and realigner CIGAR parsing without changing inference or defaults. On HG002 35x whole genome, M1 Pro (32 GiB), ten workers, batch 1024 with gVCF, measured wall time fell 8,831.4 → 7,984.3 s (9.6%) and CPU time 50,708.6 → 46,455.5 s (8.4%). All 7,709,239 VCF and 72,210,019 gVCF non-header records, including 64,500,780 reference blocks, are exactly equal to 0.4.0 by full-body SHA-256. Peak RSS grew 11.95 → 13.32 GB (about 1.4 GB); sampled temporary space was 29.4 → 29.5 GB, with zero swap growth. One run each, M1 Pro only; 16 GB base-M1 qualification remains follow-up. Requires installing the separately published native 0.4.1 binary on PATH; updating the CLI alone does not replace it (#1116, Apple Silicon performance).
  • Native wgse-deepvariant 0.4.0 supports haploid chrX/Y/MT with diploid PARs, including gVCF reference confidence. It matches Google's haploid likelihood adjustment while retaining diploid GT/PL encoding. Empty-read partitions now retain zero-depth reference evidence instead of leaving gVCF gaps. Older native builds still refuse non-diploid policies (#1103). The Linux CUDA environment pins the published 0.4.0 build 2 (#1136).
  • vcf clair3 --gpu runs Clair3's networks on the Apple Silicon GPU (MPS) through the code-only wgse-clair3 package, which pixi install -e clair3 now installs on Apple Silicon. It keeps Clair3's CPU streaming pipeline and gVCF; on a 1 Mb HG002 ONT slice its calls and gVCF reference blocks match the CPU run. CPU stays the default, and no model weights are redistributed (#1101).
  • vcf acmg runs on Windows: fastVEP 0.5.0 is now packaged by this project for Linux (x86-64, ARM64), macOS (Intel, Apple Silicon) and Windows x86-64, in the optional fastvep environment (#1164).
  • On Windows x64, bam to-cram --cram-version 3.1 uses a qualified mimalloc build of samtools with a local reference (mimalloc = "auto"), which encodes CRAM 3.1 faster; --mimalloc off keeps the system allocator. CRAM 3.0 stays the default, and other platforms and commands are unchanged (#1195).

Fixes#

  • lineage y-haplogroup --tree ftdna and --tree isogg correct independently verified ancestral/derived reversals using a pinned, separately licensed YBrowse polarity module. This fixes inverted backbone evidence and wrong haplogroup calls, including reverse-strand T2T markers. Ancient panels are filtered after correction. Version 2 requires compatible source branches and reference-lineage agreement; name-only matching in the superseded version 1 incorrectly flipped valid sister-branch markers. Use version 2, not version 1. First use requires --download; custom marker panels are unchanged (#1168, Y marker polarity).
  • repair ftdna-vcf maps FTDNA's legacy FILTER expressions to declared IDs that keep their meaning (DP=1 → DP1, QUAL<40 → Q40 and so on), instead of stripping characters into undeclared IDs or into an unrelated filter's name (q<10 → q10). Unrecognised expressions become FTDNA_UNKNOWN with a warning, and a failed call never becomes PASS (#1204).
  • Single-VCF commands use --vcf-input first and --input second, without looking for another VCF in the selected genome folder, and the manifest records only the input used (#1240).
  • analyze comprehensive uses the configured VCFs only when it is given no inputs; an explicit BAM is no longer paired with an unrelated configured VCF (#1253).
  • report asks for --input when source manifests describe unrelated samples whose input files share a name, and lists their paths, instead of merging them into one report (#1258).
  • vcf to-fasta (consensus genome) keeps uncovered bases as N for any gVCF its header declares, even when its first block starts late or it has only single-base calls (#1261).
  • serve stops on Ctrl-C or SIGTERM that arrives while a request is being dispatched, instead of continuing to listen (#1255).
  • Windows setup extracts archives correctly with the PowerShell Archive module 1.2.7, and PharmCAT reference downloads are checked so a truncated install is caught (#1146).
  • Setup checks an already installed Pixi and stops, naming its path and version, when it is older than this release requires, instead of failing later; your Pixi is never upgraded for you. On Windows only the message is shown, not PowerShell's error record (#1139, #1172).
  • Resume checks file integrity. A resumed run reuses a completed step only when its files still match: files up to 64 MiB by SHA-256, larger ones by sampled blocks plus size and modification time. Directory outputs are checked by each file's path, size and modification time, without reading them. Journals written by earlier versions have no digests, so the first resumed run after upgrading reruns each completed step once (#1202).
  • A resumable run no longer fails with "An unexpected error occurred" on macOS when a process exits while leftover tools are being looked for (#1109).

Desktop app#

  • Built-in genome viewer. Genome viewer in the sidebar, or View reads beside a BAM/CRAM/VCF input, shows reads and variants with the matching installed reference, entirely offline. BAM, CRAM and indexed VCF/gVCF results get Show in viewer; a single-region Extract custom result opens at its extracted locus. It adds local BED, bedGraph and bigWig tracks, installed RefSeq gene spans with gene-symbol search, and installed cytobands. Connect and view remote file views files on a WGS Extract server after you consent to each transfer. See the genome viewer guide (#1090, #1112, #1149, #1150, #1151, #1153, #1157, #1159, #1160, #1192).
  • Result cards. Analysis actions show their result card when the run ends, even with the terminal collapsed, and View Card shows it again. Report-writing tools (FastQC, fastp, MultiQC, Personal Report, PharmCAT) open their report (#1143).
  • Tools page. Lists every tool, installed or not, with Install and Uninstall for optional tools. An action that needs a missing optional tool offers Install and Continue, as a missing genome does (#1191).
  • The Variant Calling Default button is named for its callers: BCFTools in Basic, BCFTools, Delly in Advanced (#1190).
  • Bug-report actions stay off until setup succeeds (#1139).

See the app's CHANGELOG for details.
