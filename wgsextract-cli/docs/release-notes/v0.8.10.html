WGS Extract 0.8.10

This release ships reference library bootstrap v0.4.0 with frozen CombinedKit v3 alongside expanded CombinedKit v5, merged 23andMe v4 (v4a–c) and FTDNA v2 (v2a–d) templates, and a rebuilt CHM13 v2 site map. The desktop app adds an offline Gene page, Show in viewer links from Personal Report and mtDNA haplogroup tables, and an updated Microarray page layout. On the CLI, new workflows include offline genotype lookup, CPIC medication review (report --pgx-context), mtDNA heteroplasmy reporting, lineage y-private, qc roh, typing paraphase and target-cnv, structured repeat sizing, methylation regions, vcf prepare, panel slicing, annotation chains, cohort summarize, deps ready, parallel/ARM64 GLIMPSE2 imputation, and packaged Windows CUDA wgse-bwa and wgse-minimap2.

Changed#

  • Reference library bootstrap v0.4.0 (wgsextract ref bootstrap) expands CombinedKit v3 into CombinedKit v5 with merged 23andMe v4 (v4a–c), merged FTDNA v2 (v2a–d), and the consumer vendor formats from #1107 (Microarray: letter-named vendor variants and CombinedKit v5), plus the rebuilt CHM13 v2 site map (2,992,588 sites) and chip-revision catalogue. CombinedKit v3 stays frozen via classic v0.2.0 templates and frozen 23andMe_V4_v3 / FTDNA_V2_v3 deltas. Rerunning wgsextract ref bootstrap cleanly upgrades an existing v0.2.0 or v0.3.0 library.
  • ancestry_v2 now aliases to Ancestry_V2ab (merged v2a+v2b), and unverified/minor date- and size-qualified variants (23andme_v5_2025, ancestry_v2_2021, ancestry_v2_2024, myheritage_gsa_2025, myheritage_gsa_2025_609424) have been removed.
  • vcf impute runs GLIMPSE2's chunks side by side, one thread each, as many at once as --threads and the available memory allow (or --memory per chunk), largest first. GLIMPSE2's own threads only split work between samples, so the old one-chunk-at-a-time run used one core whatever --threads said; on chr20, 8 chunks at once took about a fifth of the time. Outputs are identical to one chunk at a time, and now reproducible at any --threads (GLIMPSE2 2.0.1's own threads sometimes changed genotypes). A failed chunk stops the others and is named in the error (#1118, imputation speed).
  • Windows x86-64 Pixi installs now include wgse-bwa, so no manual PATH or wgse_bwa_path setup is needed to use it for BWA alignment. CUDA is used automatically when available and the run fits Windows RAM and commit limits. Pass --no-prefer-native-gpu or set prefer_native_gpu = false in config.toml to force CPU.
  • Windows x86-64 Pixi installs now include wgse-minimap2, so long-read align and realign use it without manual PATH setup. CUDA is used automatically when available and the run fits Windows RAM and commit limits. Pass --no-prefer-native-gpu or set prefer_native_gpu = false in config.toml to force CPU (#1121, native Windows CUDA minimap2).
  • The Windows guide explains how to use a Dev Drive for WGS Extract work files and the risks of Defender folder exclusions (#1126, Defender overhead).
  • The experimental report finding type now accepts medication_review as a section and Not a prescription; review with a clinician. as a disclaimer. These values are for medication-review findings; other sections share the type but do not use the new values. The widened keys are:
    • wgsextract.report/1:sections.acmg_research.findings[].section and wgsextract.report/1:sections.acmg_research.findings[].disclaimer
    • wgsextract.report/1:sections.ancestry.findings[].section and wgsextract.report/1:sections.ancestry.findings[].disclaimer
    • wgsextract.report/1:sections.carrier_screening.findings[].section and wgsextract.report/1:sections.carrier_screening.findings[].disclaimer
    • wgsextract.report/1:sections.clinvar.findings[].section and wgsextract.report/1:sections.clinvar.findings[].disclaimer
    • wgsextract.report/1:sections.lineage.findings[].section and wgsextract.report/1:sections.lineage.findings[].disclaimer
    • wgsextract.report/1:sections.microarray.findings[].section and wgsextract.report/1:sections.microarray.findings[].disclaimer
    • wgsextract.report/1:sections.overview.findings[].section and wgsextract.report/1:sections.overview.findings[].disclaimer
    • wgsextract.report/1:sections.pharmacogenomics.findings[].section and wgsextract.report/1:sections.pharmacogenomics.findings[].disclaimer
    • wgsextract.report/1:sections.structural_variants.findings[].section and wgsextract.report/1:sections.structural_variants.findings[].disclaimer
  • help <command> --json loads only the requested command group. The JSON schema and its config-independent defaults are unchanged (#1493, slow test tail).
  • info calculate-coverage --by and typing target-cnv count uncovered target bases without asking samtools to scan across empty spans. Depth and breadth calculations are unchanged (#1493, slow test tail).
  • CLI version checks and help start faster. Running a command such as info no longer loads unrelated command groups (#1506, CLI startup).

New#

  • wgsextract microarray --formats combined_v3 writes <sample>_CombinedKit_v3.txt (the frozen classic 14-template CombinedKit v3 subset) alongside CombinedKit v5 (--formats all / combined_v5), so users can generate either or both combined kits.
  • On Windows x86-64, align and realign can use an optional wgse-bwa from PATH or wgse_bwa_path in config.toml. Stock BWA remains the fallback when the optional build is unavailable. The native build uses CUDA on a supported NVIDIA GPU when Windows has enough RAM and commit; --no-prefer-native-gpu forces CPU (#1119, native Windows BWA).
  • On Windows x86-64, align and realign can use wgse-minimap2 from PATH to accelerate long-read alignment on a supported NVIDIA GPU without changing the alignment records. The native CPU backend works without an NVIDIA driver; --no-prefer-native-gpu forces it (#1121, native Windows CUDA minimap2).
  • info gene --gene SYMBOL shows one gene from local files: its span, its RefSeq transcripts and exons, your VCF's carried variants in it (consequence, ClinVar, gnomAD, research-only ACMG, each tagged rare-and-damaging, ClinVar P/LP or ACMG P/LP) and BAM/CRAM depth over each exon against a callable threshold. Missing data is a notice naming the command that makes it; --export writes the rows as TSV (#1166, offline gene page).
  • ref gene-map also installs UCSC refGene's RefSeq transcript and exon models as an indexed transcripts_<build>.bed.gz; run it again to add them to an existing library (#1166).
  • extract ydna-bam --poz and extract region --target y --poz now work on T2T-CHM13v2.0 inputs, using the Poz chrY regions lifted from GRCh38 with the UCSC hg38ToHs1 chain (~11.6 Mb, bundled; no download) (#1170, T2T Poz mask).
  • lineage y-private lists candidate private (novel) Y SNPs from a BAM, CRAM or single-sample VCF on GRCh38 or T2T: called chrY SNVs inside the bundled Poz callable mask whose alleles are in no installed marker set (the YBrowse snapshot on GRCh38, YFull YTree positions on both), passing strict filters (ALT fraction ≥ 0.9, ≥ 10 ALT reads, QUAL ≥ 30). The report and result manifest state the marker sets, mask and filters, and warn when there are unexpectedly many candidates. They are candidates to confirm, not proven private SNPs (#1171, private Y SNP report).
  • qc roh finds runs of homozygosity in a VCF with bcftools roh and the population allele frequencies you give it (--af-file: a gnomAD or 1000 Genomes sites VCF, or a bcftools AF table, on the sample's build). It reports runs, marker evidence, F_ROH over the declared scope only, and the frequency file's release and digest, and flags a long run over an imprinted region (15q11-q13, 11p15.5, 14q32.2, GNAS and others) for review as possible isodisomy, which is not a diagnosis. It never downloads anything; see Runs of homozygosity (#1174, ROH and isodisomy flags).
  • report has a mitochondrial DNA section: mtDNA heteroplasmy levels at reviewed variants (ClinVar expert-panel pathogenic SNVs, release 2026-11-15) and CPIC's MT-RNR1 aminoglycoside-risk alleles, each homoplasmic, heteroplasmic, weak evidence, not detected (100x or more, ruling out 10% or more) or not assessed, with confidence, sources and a clinician-review advisory. A supported heteroplasmic MT-RNR1 allele counts as risk evidence. lineage mt-haplogroup --contamination on a BAM or CRAM now keeps mutserve's calls and per-position read table, with the mtDNA reference and mutserve version, for it (#1175, mtDNA heteroplasmy in the report).
  • Experimental output change: every report section's findings[].section can now be mitochondrial (wgsextract.report/1:sections.acmg_research.findings[].section, wgsextract.report/1:sections.ancestry.findings[].section, wgsextract.report/1:sections.carrier_screening.findings[].section, wgsextract.report/1:sections.clinvar.findings[].section, wgsextract.report/1:sections.lineage.findings[].section, wgsextract.report/1:sections.medication_review.findings[].section, wgsextract.report/1:sections.microarray.findings[].section, wgsextract.report/1:sections.overview.findings[].section, wgsextract.report/1:sections.pharmacogenomics.findings[].section, wgsextract.report/1:sections.structural_variants.findings[].section).
  • report --pgx-context FILE reviews the medications a person lists in a local TOML file against CPIC guidance (CPIC database v1.61.0, CC0, pinned; first use needs --download; the list is never uploaded). Guidance is given only when the pharmacogenomic calls it rests on are confident: weak, missing reference, unresolved Cyrius and conflicting ambiguous calls are withheld, and unsupported drugs, populations and results say so. A CPIC-quoted rule shows paroxetine's possible CYP2D6 phenoconversion beside the genetic phenotype. The review is labelled not a prescription, and the manifest records the CPIC release and the effective medication list (#1176, CPIC medication review).
  • wgsextract lookup (also the typed API's api.lookup and the server's read-only lookup operation over HTTP and MCP) answers one sample's genotype at an rsID, a build-qualified locus or a gene: the normalised alleles, depth, quality, FILTER and phase, whether it is a confident call, confident reference, weak evidence, a no-call or not assessed (a site a variants-only VCF doesn't list is never taken as reference), and what the sample's personal report says there, attributed, including analyses not run yet. Identifiers resolve offline (dbSNP build 157 merge history, the chip rsID placements of ref microarray-targets, NCBI RefSeq genes); an identifier with several matches lists them instead of picking one. See docs/lookup.md (#1178, genotype lookup).
  • Result manifests now record the public resources a run used and their exact releases (resources): ClinVar's release from its own header, CADD's SNV and indel tables, the report's gene list, each with its source terms; an unrecorded release stays unknown. ref recheck compares the recorded releases with the newest, from an answers file or, only with --online, NCBI's public ClinVar listing (no sample data is sent; nothing is downloaded or rerun). report-delta compares two reports (or any two manifests of one command and sample) by meaning: findings added, removed, reclassified or with changed review, conflicts, evidence, genotype, phase, confidence or ambiguity; changed gene interpretations; sections and runs that failed or didn't run; and changed releases, ignoring timestamps and ordering (#1179, database recheck and run delta).
  • Structured outputs now have published guarantees: output contracts classify the result manifest, personal report, sample document and HTTP responses (and the files' output roles) as stable, experimental or internal. Unvalidated scientific values such as metrics and report findings stay experimental. Every change is checked against a pinned baseline of the previous release (v0.8.9), so a stable field cannot be dropped or reinterpreted without an approved breaking change (#1180, output-contract tiers).
  • Result manifests link the runs of a BAM/VCF workflow. Each manifest has a run record with its own, root and parent run IDs and the steps it ran or reused, with the reason. Each BAM, CRAM, VCF and BCF gets an artifact record with its assembly, samples, index state, final or temporary role, producer run and source files. Variant callers and analyze comprehensive now refuse, before they start, an input on another build or reference, an index that is stale or belongs to another file, and calls of another individual. The error carries a code (assembly_mismatch, reference_mismatch, index_stale, index_mismatch, index_missing, sample_mismatch). This is a pilot; see docs/result-manifest.md (#1182, run lineage and BAM/VCF artifacts).
  • wgsextract deps ready -- COMMAND ... reports whether a command line can run on this computer without the network: its tools (version, Conda package and recorded licence), Docker images in the local engine, NVIDIA GPUs and driver, Clair3 models and wgse-deepvariant weights against their pinned SHA-256, and its input, reference genome, indexes and annotation data. Each item is runnable, installed, unverified, unsupported, missing, stale or incompatible, with the explicit setup or download step that provides a missing one. It never installs, pulls or downloads, and isn't offered by the server (#1183, offline readiness report).
  • extract ydna-bam, extract y-mt-extract and extract region --target y|ymt take --y-scope associated, which also keeps the reads on the reference's Y-associated contigs (GRCh38 chrY_KI270740v1_random, under its UCSC, GenBank or RefSeq name), as WGS Extract v4's Y and Y+MT BAMs did. A contig is kept only when its length (and checksum, if recorded) match GRCh38's; outputs are _Y_associated.* and the result lists each considered contig and why. The default --y-scope primary is unchanged (#1184, Y-associated contig preset).
  • Migrating from WGS Extract v4 maps each v44.2 button to its current desktop page and command, with changed defaults, features not yet equivalent and settings/reference precautions. NOTICE now credits WGS Extract's authors and marks the CLI's microarray export and liftover as modified GPL ports of v4 code. A differential corpus records parity and intentional differences against v44.2 on synthetic and public HG00096 data; its public inputs download only with --download (#1187, v4 migration guide and corpus).
  • typing paraphase calls copy number and haplotypes at paralogous loci such as SMN1/SMN2 and PMS2 from PacBio HiFi whole-genome reads. It writes TSV and JSON calls, retains the engine's raw files, and labels ONT calls experimental and unvalidated (#1285, long-read paralog typing).
  • typing target-cnv screens BED targets for copy number in short-read WGS on GRCh37, GRCh38 and T2T-CHM13v2.0. It works offline, flags difficult targets for specialist callers, and reports clear depth calls at curated whole-gene deletion loci (#1285, target copy number).
  • typing str --loci HTT,FMR1,AR sizes only the named catalog loci. --format parquet writes a typed repeat table, and the result JSON includes numeric allele sizes, confidence intervals and read support. The personal report now summarizes flagged, unconfirmed and normal repeat calls (#1286, structured repeat sizing).
  • Report findings can name the new repeat_expansions section, so the experimental section field of every report section's findings accepts that value: wgsextract.report/1:sections.acmg_research.findings[].section, wgsextract.report/1:sections.ancestry.findings[].section, wgsextract.report/1:sections.carrier_screening.findings[].section, wgsextract.report/1:sections.clinvar.findings[].section, wgsextract.report/1:sections.lineage.findings[].section, wgsextract.report/1:sections.microarray.findings[].section, wgsextract.report/1:sections.overview.findings[].section, wgsextract.report/1:sections.pharmacogenomics.findings[].section, wgsextract.report/1:sections.structural_variants.findings[].section (#1286, structured repeat sizing).
  • panel check validates a research panel file (wgsextract.panel/1, TOML or JSON): gene groups with variant filters, watched sites and haplotypes. It lists every problem with its location, resolves the genes offline in the bundled NCBI RefSeq annotations with their coding lengths, and warns about unknown or ambiguous gene names. Research use only; it reads no sample data. The format's JSON Schema is assets/schemas/wgsextract.panel.1.schema.json (#1287, declarative research gene-panel audit).
  • The bundled gene annotations now carry each gene's HGNC ID and the coding length of its MANE Select (else RefSeq Select, else longest) transcript, and panel bed accepts HGNC IDs (HGNC:613) as well as symbols (#1287).
  • cohort summarize writes local autosomal SNV counts and frequencies from multiple variant VCFs and their matched gVCFs. It distinguishes reference calls from missing evidence and omits sample names and source paths by default (#1288, local cohort aggregation).
  • vcf table now exports phase sets, per-allele read fractions, transcript IDs, and gnomAD ancestry-group maximum frequencies and homozygote counts when available. The added columns are also queryable through HTTP and MCP (#1289, variant table columns).
  • vcf table adds ad_ref and ad_alt, the sample's FORMAT/AD read counts for allele-balance queries. They stay empty when AD is missing or incomplete. /v1/variants and MCP query_variants can return both columns. Variant table has new example queries for ancestry-common variants, cis/trans phasing and skewed allele balance (#1289, vcf table phase, allele fraction and transcript columns).
  • vcf filter and vcf table can keep variants from multiple genes, a gene list, a preset, or a BED panel, all offline. Combine them in one run and optionally narrow the panel with --region. The result manifest records the intervals used and the BED's SHA-256 (#1290, VCF panel slicing).
  • vcf chain-annotate accepts --threads, targets a region or BED panel, and resumes after a failed annotation step. Add --to-table to write a TSV (or Parquet) and SQLite database in the same run (#1291, targeted and resumable annotation chains).
  • vcf prepare repairs VCFs from sequencing services that other tools reject: it recompresses plain gzip, text and BCF to BGZF, sorts, declares missing contigs and IDs, renames and sizes contigs to match --ref, rebuilds the index and, with --normalize, splits multiallelic records and left-aligns indels. Every repair is reported with its counts, and no record is dropped (#1292, VCF preparation).
  • methylation regions --partition-hp summarizes HP1, HP2 and unphased CpG calls from an indexed haplotagged BAM or CRAM. Differences are only reported for a coherent phase set and sufficient shared coverage. The new table is wgsextract.methylation-regions-hp/1; it adds partition, phase_status, phase_set, shared_qualified_cpgs and hp1_minus_hp2_pp. The manifest records output role:methylation_regions_haplotypes, optional input role:phase_blocks, and method metadata under wgsextract.result/1:details.haplotype_partition (#1293, haplotype-resolved methylation region summaries).
  • methylation regions summarizes precomputed CpG calls by RefSeq gene promoter or UCSC CpG island on GRCh38 and CHM13v2.0. It writes TSV or Parquet, distinguishes low coverage from zero methylation, and runs on native Windows without modkit (#1293, methylation region summaries).
  • vcf impute and ref imputation now use native GLIMPSE2 on Apple Silicon and Linux ARM64 through pixi install --locked -e imputation (#1398, native ARM64 GLIMPSE2).
  • vcf pharmcat --alignment uses a local BAM or CRAM to fill absent definitions only where mapped reads support a reference genotype. It overrides companion gVCF discovery and cannot be combined with --absent-to-ref. The new experimental wgsextract.result/1:details.pharmcat_reference_evidence summary and role:pharmcat_reference_evidence report record the source and thresholds, how many absent definitions were filled, and how many stayed missing. The report also lists the missing positions.

Fixes#

  • lineage y-str now calls DYS448, DYS459 and DYS589 on T2T when reads support a call. DYS589's non-repeat boundary variation no longer appears as a fractional STR allele. DYS425 is left blank on all builds because short reads cannot reliably distinguish its assay target from paralogs (#1155, missing Y-STRs).
  • score pgs --trait bmi now uses PGS005198, the GIANT consortium's multi-ancestry BMI score (Smit et al. 2025, CC BY 4.0), instead of PGS000027, which only academic research may use. Its ancestry-adjusted percentiles need the new reference release pgs-ref-2, so the first run after upgrading needs --download again. CC BY 4.0 scores no longer warn pgs_license_restricted (#1165, BMI score).
  • Cancelling a command now stops its subprocess tree. ref bootstrap no longer retries a cancelled download, and ref gnomad disconnects stalled downloads on cancellation (#1213, cancellation cleanup).
  • An interrupted reference download no longer resumes onto a different version of the file. Resumes were tied to the URL alone, so a file replaced at the same URL by one of the same size was installed as the old file's start and the new file's end. Both one-connection and segmented downloads now record the server's ETag or Last-Modified date, resume only that version and otherwise start over. A partial left by an earlier release, or from a server that names no version and without a pinned checksum, downloads again from the start (#1225, resumed downloads mixing file versions).
  • wgsextract serve: a job whose worker started but could not be given its request or have its record saved (for example on a full disk) now fails with the reason, stops its worker and frees its slot. Before, it stayed running with an orphaned worker and later jobs waited forever (#1226, server job startup failures).
  • The server's /v1/viewer-file answers a HEAD without a Range with 200 and the file's full Content-Length for files over 32 MiB, instead of 416; whole-file GETs keep their 32 MiB limit (#1227, viewer HEAD on large files).
  • Saving settings from the desktop app and from wgsextract at the same time no longer loses one of the changes: each save of config.toml now waits for the other and merges into the file as it is, also when the file is reached through a symlinked folder (#1230, lost concurrent config saves).
  • score pgs now finds bcftools the same way its dependency check does, so it scores when bcftools is installed only in the WGS Extract Pixi environment rather than on PATH. It previously failed with "No such file or directory: 'bcftools'" (#1233, PGS bcftools probes).
  • Output folders on drives without hard links (exFAT, FAT32 and some SMB shares) now work: qc multiqc no longer fails with "Operation not supported", nor do whole-genome GATK, Clair3 and DeepVariant calls that split the genome by ploidy. An existing report is still never replaced without --force (#1241, drives without hard links).
  • microarray gives the same kit from a plain .vcf or an unindexed .bcf as from the same calls bgzipped and indexed. Such input skipped matching its chromosome names to the targets' (1 or chr1, MT or chrM), so every marker became a no-call, and --region failed. It is now compressed and indexed in the run's temporary work, never beside the input, in its own record order (sorted only when unsorted); kits made from it before are regenerated (#1242, unindexed VCF no-calls).
  • microarray and lineage y-haplogroup now read gnomAD-style .vcf.bgz

files and upper-case VCF names such as KIT.VCF.GZ as VCFs, rather than treating them as alignments or refusing them; lineage mt-haplogroup also accepts .vcf.bgz. Reference builds that earlier versions recorded in a sample workspace are detected again (#1243, .vcf.bgz not recognised).

  • vep run on a BAM or CRAM of T2T or an unrecognised build no longer calls variants with GRCh38's or GRCh37's ploidy preset, whose sex-chromosome coordinates don't fit it. Like vcf snp, it uses the reference library's ploidy file (ploidy.txt also serves an unrecognised build, and --assembly picks that assembly's file) or asks for --ploidy or --ploidy-file. An --assembly that contradicts the alignment's header or its reference's index is refused (#1244, wrong-build ploidy).
  • ref cadd keeps a complete CADD score table whose index download failed or was cancelled: the next run checks the table against its published MD5 and fetches only the missing index, instead of downloading the ~85 GB SNV table again. A table in place that fails the check is reported, not removed. ref revel now downloads over https and checks each file against a pinned SHA-256 (#1245, CADD index retry and REVEL integrity).
  • uninstall.sh no longer deletes a Pixi environment or cache directory outside the installation whole, which removed other Pixi projects' environments sharing it. It now removes only this installation's environment folder, and an external cache only if the installer created it; installs from earlier versions keep their external cache. It lists exactly what it will delete before asking to continue, and --remove-config refuses a symlinked users workspace before deleting anything rather than after removing the installation (#1246, uninstall removes shared Pixi folders).
  • Depth estimates and parallel variant calling now recognise plain-text CRAM indexes (.crai) as well as gzip-compressed indexes.
  • Workflow steps now restore their inherited process tag, so nested workflows don't lose the tag used to identify tools from an interrupted run (#1248, core edge cases).
  • Delly SV and CNV calling and Sniffles now accept comma-separated regions and BED files. pbsv rejects both forms and still accepts a single region (#1250, multi-region structural calling).
  • Confidence labels no longer treat zero-sum FORMAT/AD (0,0) or a missing AD count without FORMAT/DP as evidence of allele_imbalance. They use another available read-fraction measure or report allele_balance_unknown (#1289, vcf table phase, allele fraction and transcript columns).
  • report-issue now reads sample names from a BAM/CRAM or VCF header when samtools or bcftools is installed only in the WGS Extract Pixi environment rather than on PATH, so it redacts them from the report. It previously could not start the tools and left those names in (#1314, report sample redaction).
  • The CLI follows an old --config path when the desktop app moved the file and the old path no longer exists. (#1322, workspace move coordination)
  • Every command that calls variants from a BAM or CRAM now follows one ploidy policy: --ploidy or --ploidy-file, else the reference library's ploidy file, else bcftools' GRCh37 or GRCh38 preset. A T2T or unrecognised build, whose sex-chromosome PARs no preset fits, is refused with the fix (the command's ploidy option, or ploidy_<build>.txt in the reference library) instead of borrowing another build's preset. microarray on an unrecognised build no longer calls every chromosome diploid, and vcf trio, GATK, Clair3 and DeepVariant calling and benchmark share the same refusal (#1334, T2T ploidy preset).
  • Variant callers no longer choose a build-specific ploidy table from a file name, folder name or contig count alone. Supply a ploidy explicitly if the input and reference cannot establish the build; vep run can also use an explicit --assembly (#1346, name-only ploidy presets).
  • vep run now refuses a FASTA that disagrees with the BAM or CRAM header or --assembly, even when the alignment and --assembly agree (#1435, mismatched VEP reference).
  • vcf table distinguishes missing gnomAD frequencies from low frequencies. A vep-rs cache from vep download gives VEP 1000 Genomes frequencies only (Ensembl publishes no gnomAD ones to build from); the table keeps them in new kg_af and max_af columns, never in gnomad_af. The SQLite metadata records population_af_sources, and the manifest reports gnomad_af_rows, kg_af_rows and max_af_rows and warns gnomad_af_missing, pointing to vcf gnomad. vep run lists the missing gnomAD frequencies in vep_cache_gaps. The help for vep download --variations names 1000 Genomes, and when VEP lists several co-located frequencies (0.1&0.4), the table reports the highest (#1354, vep-rs gnomAD frequencies).
  • On Windows, sign verify now checks for a working OpenSSH verifier and can use Git for Windows when the inbox OpenSSH hangs. If no working verifier is available, the error identifies the builds tried and how to use a working one (#1358, Windows signature verification hang).
  • On Windows, sign create now times out instead of hanging in OpenSSH and does not leave an incomplete signature behind.
  • The Python API records a command's input files under the same result manifest roles and params as the CLI. A VCF given as vcf_input (for vcf operations on a VCF and qc vcf) is role vcf_input with provenance.params.vcf_input set, not role input; a vcf trio proband is role proband; and r1/r2 reads are fastq_r1/fastq_r2 (#1367, API input roles).
  • extract ydna-vcf --ybrowse works with GRCh38 references that mask the chrY PARs with N (hs38, hs38DH, the no-alt analysis set). yBrowse sites where the reference is N are skipped and counted in the VCF header and a ybrowse_reference_n_sites_excluded warning, instead of stopping the run with "Reference allele mismatch ... REF_SEQ:'N'". Other REF mismatches still stop it (#1374, yBrowse calling on PAR-masked GRCh38).
  • On Windows, wgse-bwa uses Segment Heap to avoid stalling CUDA mate rescue while CPU workers wait for heap allocations. align and realign select CUDA automatically when the Windows RAM and commit checks pass. Use --no-prefer-native-gpu to force CPU. Alignment records are unchanged (#1403, Windows CUDA mate-rescue performance).
  • Cancelling parallel imputation stops queued chunks from starting and terminates running tools promptly (#1415, job pool cancellation).
  • gnomAD 4.1 frequency tables now retain the maximum ancestry-group frequency and homozygote count for each alternate allele. Rebuild older tables with ref gnomad --release 4.1 --download to get one row per passing alternate allele, even if the old table already has all the columns (#1419, gnomAD joint frequencies).
  • ref gnomad needs --download before fetching either release.
  • The mockup server watchdog alerts when the server goes down or recovers, or when the failure reason changes. During an ongoing outage it reminds agents every four hours instead of every five minutes. See #1451 (watchdog alert spam).
  • api.vcf.table() now closes its subprocess pipes on success and failure, avoiding Python's unclosed-file warning (#1473, VCF table pipe leak).
  • vcf deepvariant can call decoy-rich references such as hs38DH when the ploidy policy excludes a contig. It passes the selected intervals in a BED file instead of exceeding GNU parallel's command-line limit (#1491, oversized DeepVariant region selection).
  • qc roh now shows why tabix could not index the allele-frequency table and suggests sorting only when tabix finds an ordering problem. VCF indexing errors also no longer suggest sorting when tabix reports a different failure (#1519, misleading tabix errors).

Desktop app#

Added#

  • The Microarray page keeps CombinedKit v3 alongside CombinedKit v5 (expanding v3), places 23andMe v1/v2 before v3 and FTDNA v1 (Affy) before v2 on their main rows, puts FTDNA's GRCh38 Y formats (v2y, v3y, v4y) on a dedicated FTDNA (Y only, Build 38) row, exposes the consumer vendor formats from #1107 (Microarray: letter-named vendor variants and CombinedKit v5) (AncestryDNA v2ab, v2cd, v2e; FamilyTreeDNA v4; MyHeritage v3; tellmeGen, Genera, MTHFR Genetics, meuDNA v1/v2, SelfDecode, and Nucleus), and removes the dropped minor date/size variants and standalone ancestry_v2.
  • A result's findings (Personal Report) and mtDNA haplogroup variants are listed under it, each with Show in viewer at its own position on the sample's BAM, CRAM or VCF. The viewer opens a row's contig in the matched reference's spelling (chr1 or 1, chrM or MT), opens ClinVar and ACMG findings only on a reference of their evidence's build, and opens Haplogrep's rCRS positions only on a mitochondrion whose sequence is the rCRS (not hg19's Yoruba or T2T's CHM13 chrM). A row without a single position, or whose sample file is missing, unindexed or outside My Genomes, shows a disabled link with the reason; POST /api/viewer/check checks the file without granting any bytes (#1161, viewer links from result tables).
  • A Gene page in the WGSExtract sidebar: enter a gene symbol to see its RefSeq transcripts and exons, your variants in it (consequence, ClinVar, gnomAD, research-only ACMG; filters for rare and damaging, ClinVar P/LP and ACMG P/LP; Export TSV) and read depth over each exon against a callable threshold, all from wgsextract info gene on this computer. Missing data names the command that provides it; Open in genome viewer shows the gene with the new RefSeq transcripts track (gene-page.md, #1166, offline gene page).
  • VCF Info, VariantQC, Granite-QC, and multi-VCF picker actions, provenance tooltips on Reference Data/Genomes/Tools tables, and genome viewer rsID and annotation tracks (#1463, VCF Info/QC/Viewer tools).

Fixed#

  • The genome viewer's file endpoints answer a HEAD without a Range with 200 and the file's full size for files over 32 MiB too, instead of 416; whole-file GETs keep their 32 MiB limit (#1227).
  • Two settings saves at once, from two windows or from the app and the CLI, no longer lose one of the changes: each save takes a lock the CLI shares and merges into the file as it is (#1230, lost concurrent settings saves).
  • A run, setup or workspace move whose window disconnected before its progress stream began no longer starts, instead of running (and holding the workspace) with nobody listening; a progress write waiting on a stalled window always settles when the stream is cancelled (#1234, backpressured progress on disconnect).
  • Moving the users workspace or a library folder keeps the symbolic links in it working, on the same disk or to another one. A link to a file inside the moved folder now points at that file's new place (a relative link stays relative), instead of at the old folder; a link to something outside the folder still points there, and is moved as a link, never copied in. Windows folder links fall back to junctions when symbolic links aren't allowed (#1239, links broken by a move).
  • Moving the users workspace or a folder named in Settings now asks you to retry if a command or save is still running, instead of risking lost changes or output in the old folder. A refused move does not interrupt the steps of an already-running CLI workflow. (#1322, workspace move coordination)
  • Settings refuses a move if the user's workspace, the library folder being moved, or the chosen destination is itself a symbolic link or Windows junction. The error names the link and its target; nothing is moved or changed. To relocate a linked folder, move its target manually and update the setting. For a linked destination, select the actual folder instead of its link. Links inside the folder being moved are unaffected (#1340, moving a linked folder).
  • The next job starts a fresh local job server after all running processes are stopped (#1459, job server restart).
