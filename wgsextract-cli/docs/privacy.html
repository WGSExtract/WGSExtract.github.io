Privacy and network access

Scope: This document covers WGS Extract CLI (the command-line back-end, Python API and local server). For the desktop app's privacy model — including automatic update checks, interactive missing-data install prompts, and how the GUI sits atop the strictly offline CLI — see Desktop App Privacy and network access and GUI Architecture — Privacy and network boundary.

Ordinary analysis, inspection and reporting stay on this computer. Defaults must not attempt a connection, even when a reference, tree, gene list or model is missing. There is no telemetry, usage reporting or background CLI update check. Missing dependencies are reported, never installed by analysis. Runtime Pixi invocations use both --no-install and --frozen: skipping installation alone would still allow lockfile resolution and registry queries. Incomplete installed runtimes fail with setup guidance, rather than falling back to a potentially different CLI on the host's PATH.

Explicit download/install commands may use the network. Other commands need --download before fetching missing public data. Without permission they name the missing data and explain how to confirm the download. Installed, verified data is reused offline. --no-download overrides a persistent opt-in:

# config.toml; default is false
allow_reference_downloads = false

ref cytobands validates installed tables offline and requires its own explicit --download to fetch missing UCSC cytoBand data, even if the persistent setting is enabled. The request contains only the hg19/hg38 public assembly path on hgdownload.soe.ucsc.edu; no sample-derived data is sent. The genome viewer uses installed tables only and never requests UCSC data.

analyze comprehensive runs these same guarded subcommands. Provision missing data first with the download command named in the error, or explicitly opt in through config.toml before running the comprehensive workflow. The desktop exposes the same default-off setting under Settings → advanced settings → Allow missing public-data downloads, with the request disclosure in its tooltip. Lineage and microarray pages also offer an unchecked per-run download option. Fresh-install automation plans select it explicitly; ordinary runs do not.

The option is shared by the CLI and typed Python/server parameters. The read-only MCP surface refuses download permissions. A server job needs both job authorization and download permission; merely starting the server grants neither to an analysis. Do not enable downloads globally on a machine that must remain offline.

Checking a run before going offline#

wgsextract deps ready -- COMMAND ... reports whether a command line can run here without the network, before a long run or before disconnecting. It checks each prerequisite with the check the command's own run makes: the platform, the tools it runs (with their versions, Conda packages and the licences their metadata record), Docker images in the local engine (identity, digests, labels), NVIDIA GPUs and driver, Clair3 models and wgse-deepvariant weights against their pinned SHA-256, and the input, reference genome, indexes and annotation data. Each item is runnable, installed, unverified, unsupported, missing, stale or incompatible; a missing one names the explicit setup or download step that provides it (deps install, ref library --install, docker pull, ref verify, bam index). The check installs, pulls and downloads nothing and makes no network request; a command that downloads, or a remote input, is reported as needing the network. It exits 3 when the run isn't ready. Model and weight terms show as unknown where nothing installed records them: installing, verifying or signing a component doesn't grant a right to redistribute it. The server doesn't offer the check, since its command line names paths on the host.

wgsextract deps ready -- vcf clair3 --input ont.bam --gpu
wgsextract --json deps ready -- vcf deepvariant --input sample.cram

What goes where#

Public-data requests reveal your IP address, requested asset/model identifiers, HTTP headers and timing. GitHub downloads can redirect to GitHub's release asset CDN; checksum discovery may request api.github.com. Audited resource mirrors, when available, use byte-identical public assets and the same consent. A mirror is not permission to download. No reference download sends sample files, genotypes or variant coordinates.

vep run uses a local cache and fails if the required Ensembl cache is missing. Choosing --engine ensembl does not authorize sending variant queries. The separate vep download command fetches public data only.

Opening an external report/documentation link is an explicit browser action; the browser's own privacy settings apply. Generated reports do not load remote scripts, fonts or images automatically. The desktop's UI and job server talk over authenticated loopback connections on this computer. The optional remote genome viewer uses that local backend to proxy explicitly selected server file ranges. Importing or restoring its private TOML configuration makes no remote request. The backend keeps the server token outside browser-delivered data; the viewer receives revocable per-file grants. HTTPS retains certificate validation; redirects and cookie forwarding are disabled. Plain HTTP exposes credentials and genomic traffic, so use an operator-managed TLS proxy or encrypted tunnel. Opening the desktop's Reference Genomes page reads only local/catalog metadata and cached sizes, including old sizes. Look up sizes requires confirmation of the destinations and requests before any remote size lookup.

PR #1019 (ACMG site-restricted annotation data) is coordinated separately: its proposed remote tabix reads reveal sample-derived variant byte ranges to Google Cloud Storage and Ensembl. That must never be an automatic fallback, including on a missing local database. Its explicit sample-position permission is distinct from permission to download a complete public reference. On the audited main revision, vcf acmg requires local prepared databases; the SpliceAI auto-fetch belongs to the explicit ref acmg-data preparation command.

Regression coverage blocks Python DNS/socket connections while representative local commands process tiny synthetic data, checks first-use refusal and explicit consent, and retains real samtools/bcftools. Subprocess network isolation is used where the host permits an unprivileged network namespace; socket monkeypatches alone do not sandbox C extensions or child processes.
