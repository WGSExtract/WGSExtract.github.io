Genotype imputation (vcf impute)

wgsextract vcf impute fills in a GRCh38 sample's genotypes at the sites of the 1000 Genomes 30x reference panel (3,202 people, NYGC, phased):

  • Low-coverage reads (a BAM or CRAM at about 0.5–8x) with GLIMPSE2 (Rubinacci et al. 2023, Nature Genetics; MIT). GLIMPSE2 reads the reads at every panel site and combines what little they show with the haplotypes of the panel.
  • Genotype-only VCFs, such as microarray calls, with Beagle 5 (Browning et al. 2021; GPL-3, run as a separate program).
pixi install -e imputation                                    # once: GLIMPSE2, Beagle, Java
wgsextract ref imputation --install --chromosomes chr20      # once per chromosome
wgsextract vcf impute --input lowpass.cram --chromosomes chr20
wgsextract vcf impute --vcf-input chip.vcf.gz

Above about 8x, call the reads directly (vcf snp, vcf deepvariant): imputation adds little there and can only find variants the panel holds. vcf impute warns (high_depth_imputation) when the reads are deeper.

The reference panel#

ref imputation --install --chromosomes chr20 (or chr1-22, or all) downloads each chromosome's panel VCF from IGSR and GLIMPSE's genetic map, checks both against pinned SHA-256 digests, keeps the panel's biallelic SNPs and writes GLIMPSE2's binary reference chunks. The download is deleted; the SNP panel plus binary references require roughly 70 GB for all autosomes. It checks for free space of 2.5 times the requested downloads first.

The panel is GRCh38 only, with contigs named chr1, chr2...; chrX needs each sample's ploidy and isn't supported yet. A chip VCF with contigs named 1, 2... is renamed for you. Contig lengths must be present to verify GRCh38; for a lengthless header, supply the matching GRCh38 FASTA index with bcftools reheader --fai GRCh38.fa.fai first.

The optional environment supports Linux and macOS (x86-64 and ARM64) and Windows x64. pixi install --locked -e imputation installs native GLIMPSE2 2.0.1 on Apple Silicon and Linux ARM64. The ARM64 packages use NEON without emulation; the HG002 fixture produces identical variant records to Bioconda's x86-64 build on the same OS. If an Intel binary on your Mac's PATH fails to start, move it off PATH to use the native Pixi build; Intel binaries need a compatible Rosetta runtime. If you already prepared a panel with the Intel build, rerun ref imputation --install for the same chromosomes to rebuild the binary chunks from the local panel.

On Windows, pixi install -e imputation installs our native GLIMPSE2 2.0.1 package from the glimpse2-1 release, pinned by URL and SHA-256 in pixi.toml, alongside conda-forge's native OpenJDK and the pinned noarch Beagle jar. No MSYS2 or WSL runtime is needed; GLIMPSE2 phase requires an AVX2/FMA-capable CPU. Windows CI tests a fresh install and both tools on the real HG002 fixture without skips. Missing tools fail dependency validation; neither feature command installs tools. Windows ARM64 remains unsupported. The server must allow the effective reference library and panel paths, not just the FASTA's genomes/ subfolder; configured defaults and symlinks are checked too. Failed or version-mismatched binary-chunk builds also recheck disk space on retry (about 1.6 times the download size for pending chunks).

Output and labelling#

imputed.vcf.gz (+ .tbi) holds every panel site of the chromosomes imputed:

  • INFO/IMP marks an imputed genotype. GLIMPSE2's are all imputed; Beagle leaves the chip's observed genotypes unmarked. Missing chip genotypes are removed before Beagle, so their filled-in calls are marked IMP too. Previously imputed source calls are also removed rather than promoted to observed chip genotypes.
  • FORMAT/GT, DS (dosage) and GP (genotype probabilities), and the site's INFO score: GLIMPSE2's INFO/INFO (with the panel frequency INFO/RAF), Beagle's INFO/DR2. Beagle output also keeps the reference panel's counts as WGSE_PANEL_AC/WGSE_PANEL_AN. These dedicated fields survive sample subsetting; standard AC/AN can be recalculated from one sample. Beagle's own AF is also a target-sample frequency. Neither unqualified AF nor ordinary AC/AN establishes panel rarity.
  • FILTER ImpLowConf on imputed genotypes whose most likely genotype has GP below --min-gp (GLIMPSE2: 0.9; Beagle: 0.95). There is no default INFO or DR2 filter. --min-info remains an explicit opt-in site filter, meaningful only for multi-sample cohorts, not single-target imputation.
  • A header line ##wgsextract_imputation=<Tool=...,Version=...,Panel=...>.

Downstream commands use these labels:

  • qc vcf warns that the file is imputed (imputed_vcf).
  • vcf table has an imputed column and the genotype's probability (variant-table.md).
  • Confidence labels (variant-confidence.md) make every imputed call low (reason imputed), and an imputed allele rarer than 1% in the panel is never listed as a ClinVar or rare-variant finding.
  • microarray exports ImpLowConf genotypes as no-calls, not as the reference. Targets absent from an imputed VCF are also no-calls: the panel did not assess them, so they cannot be filled as homozygous reference.

Per-genotype confidence for single-target imputation#

The command takes exactly one target sample. Beagle's DR2 measures dosage spread across target haplotypes: with one sample it acts largely as a zygosity indicator. Confident hom-ref and hom-alt calls can have DR2 zero. Any positive default DR2 cutoff therefore discards genuine homozygous calls and turns them into chip-export no-calls. Do not use it as genotype confidence. GLIMPSE INFO is also a site statistic, not a substitute for the target's GP. Both scores are retained in the output, but neither is filtered by default.

Use the per-genotype max GP instead: Beagle defaults to 0.95; GLIMPSE2 to 0.9. The GP curves score common (panel MAF >5%) sites inside GIAB's confident BED, excluding Beagle's chip-input positions. They are retained in out/621/gp/; the earlier DR2 calibration is superseded.

Resources#

Measured on lin-big with four threads, before chunks ran side by side:

GLIMPSE2's --threads only splits work between target samples, and vcf impute imputes one, so those four threads did no more than one (#1118, imputation speed). vcf impute therefore runs --threads chunks at once, one thread each, largest first. Each chunk's peak memory is estimated from its binary reference (about 1.2 GB for a typical chunk, 3 GB for chr20's centromeric one), and chunks start only while the running ones fit in 80% of the memory available when the command starts, or in --memory per chunk; one always runs. Each chunk's output doesn't depend on how many run, so the result is identical to running them one at a time. (GLIMPSE2 2.0.1's own threads, used before, sometimes changed a chunk's genotypes from run to run.) A failed chunk stops the others, and the error names it and quotes GLIMPSE2's message.

On an M1 Pro (10 cores, 32 GB, a shared host, so absolute times are pessimistic), vcf impute of HG002 1x chr20 (26 chunks, 1,430,673 sites) with Bioconda's x86-64 GLIMPSE2 2.0.1 under Rosetta took:

The three new runs wrote identical genotypes, dosages and probabilities. The old --threads 4 run differed from them at 798 genotypes. The native ARM64 build phased these chunks in 479 s one at a time and 100 s eight at once in the initial #1118 speed study. Preparing the chr20 panel took 577 s.

Extrapolating chr20 (about 2.2% of autosomal bases) gives about 5.6 hours for whole-autosome GLIMPSE2 one chunk at a time, and about 1 hour with eight at once, needing about 10–14 GB at eight. Beagle extrapolates to about 45 minutes. These are projections, not measured whole-genome runs, and exclude panel preparation. vcf impute prints its selected-chromosome time/RAM estimate before running.

The Phase 0 scripts, per-bin JSON, time.tsv and logs are retained in out/621/phase0/ in the validation checkout, with the result summary on issue #621.

Product-command validation#

The actual ref imputation --install --chromosomes chr20 and vcf impute commands were run on lin-big against the same 1x BAM, under an agent-coord four-core/8 GiB lease (nominal 1x input; product depth estimate 1.15x). The installer reused and SHA-256-verified the original download on that host, then prepared its own panel and binary chunks.

The corrected Beagle product command was also run end to end on chr20, with the same chip VCF and product panel, under a four-core/ 8 GiB lease. Its dosage r² exactly matches Phase 0 in every MAF bin, including 0.941519598 (5–20%) and 0.933948882 (20–50%).

The actual output FILTER values, not just a reconstructed threshold, give 123,445 / 136,208 common sites PASS (90.63%) and aggregate NRC 0.973671875. All 18,489 / 18,489 GP-qualified hom-alt calls in these evaluated sites are PASS; there are zero disagreements between the output filter and the GP-only rule. The header records MinGP=0.95 without a MinINFO condition, and the manifest reports the site filter as disabled.

The product wrote 1,416,853 imputed sites (27,740 ImpLowConf), took 2 min 34 s including input preparation/labelling, and peaked at 2.2 GB RSS. Evidence is in out/621/product-beagle/; its large VCF remains at /mnt/models/wgse-621/out/621/product-beagle/output/.

The no-call fixture probe at chr20:10,008,603 is filled as 1|1, GP=1, DR2=0, PASS and IMP, and its exported table row has imputed=1. It is a direct regression for both the homozygote filtering and missing-probe labelling bugs. Panel-rarity suppression remains in force for imputed calls.
