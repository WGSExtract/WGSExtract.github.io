Repairing FTDNA VCF files

Older FamilyTreeDNA (FTDNA) Big Y variants.vcf files write expressions such as DP=1 or QUAL=12.5 in the FILTER column. VCF allows only IDs there, each declared by a ##FILTER header line, so bcftools, VEP and other tools reject or misread those records. wgsextract repair ftdna-vcf rewrites the column into declared IDs that keep the failure's meaning:

wgsextract repair ftdna-vcf --input variants.vcf        # writes wgse/variants_repaired.vcf
bcftools view variants.vcf | wgsextract repair ftdna-vcf > fixed.vcf

The repair runs offline and needs no reference data. It reads plain, gzipped or BCF input (BCF needs bcftools) and writes plain VCF.

FILTER mapping#

Each ;-separated entry of a FILTER value is handled on its own:

Input entryOutput IDHeader description
PASS or . (whole value)unchangedunchanged
an ID declared in the header (LowQual, VQSRTrancheSNP99.90to100.00+)unchangedthe input's own
a valid ID the header doesn't declareunchangeddeclared as "meaning unknown"
DP=1DP1a single read covers the site
DP=n, n > 750DPMmore than 750 reads cover the site
DP=n, 2 ≤ n ≤ 750DPFfailed an FTDNA depth filter of undocumented threshold
QUAL=q, q < 40Q40site quality below 40
QUAL=q, q ≥ 40QFfailed an FTDNA quality filter of undocumented threshold
GTL=xGTLfailed FTDNA's undocumented GTL filter
anything else (Low Coverage, DP<5, an empty value or ;)FTDNA_UNKNOWNfailed a vendor filter of unknown meaning
  • A failed call never becomes PASS: PASS next to a failing entry (PASS;DP=1) is dropped, and the remaining failure is kept. A value of only PASS entries (PASS;PASS) becomes PASS, one of only . entries (.;.) becomes ., and . or empty entries beside others (PASS;, .;DP=1) are dropped: an empty separator is not evidence of a failure.
  • Several entries stay several IDs (DP=1;QUAL=19.1 becomes DP1;Q40).
  • Each replaced expression is kept, percent-encoded, in INFO/FTDNA_FILTER (DP%3D1,QUAL%3D19.1), so the original evidence is still in the file.
  • Only IDs the records use are declared, and new declarations go just before the #CHROM line. An input whose FILTER values are all valid and declared, and that has no undeclared HG/ISOGG keys, is copied unchanged.
  • If the input already declares one of these IDs, or INFO/FTDNA_FILTER, with another description, the repair keeps the input's declaration and uses a new name (DP1_WGSE) for its own category.
  • INFO/HG and INFO/ISOGG values are copied as they are. If records use them without a header declaration, they're declared as Number=.,Type=String; the repair never adds haplogroup values. Filling them from yBrowse is a separate, explicit step (see Lineage).

Warnings and failures#

The result manifest (--json) counts records, repaired_records and unknown_filter_records, and carries structured warnings:

CodeWhen
ftdna_vcf_unknown_filterSome entries matched no rule and became FTDNA_UNKNOWN
ftdna_vcf_undeclared_filterValid IDs were used without a declaration
ftdna_vcf_id_conflictA mapped ID was renamed because the input already used it

A record before the #CHROM line, a missing #CHROM line or a record with fewer than eight columns stops the repair with an error. The repair reads the whole input first, so malformed input produces nothing on stdout in pipe mode. When using --input, the output cannot be the input file, even through a hard link. If the output is a symlink, choose a regular file path instead. The command writes to a temporary file next to the destination and replaces the destination only on success. A failed repair leaves any existing output intact. On Unix, the repaired file is private to the current user, even when replacing an existing output. Empty input gives empty output. Records beyond 64 MiB are held in an unnamed temporary file in --tmp-dir (or the temp_directory setting), else beside the output, else the system temporary folder; memory use doesn't grow with the number of records.

Differences from WGS Extract v4#

WGS Extract v4's standalone fixFTDNAvcf.py declared PASS, DP1, DPM, Q40 and GTL and the HG/ISOGG INFO keys in every file, then mapped each entry by substring: DP=1 to DP1, any other DP= to DPM ("More than 750 reads"), GTL= to GTL and QUAL= to Q40 ("Quality below 40"). This command differs in that it:

  • checks the value, so DP=37 and QUAL=55 don't get a description that is untrue for them (DPF and QF instead);
  • keeps already-valid IDs such as LowQual and declares undeclared ones, where v4 blanked every entry it didn't recognise, which could leave an empty FILTER or a bare ;;
  • maps unrecognised expressions to the declared FTDNA_UNKNOWN and warns, rather than dropping them;
  • keeps the original expressions in INFO/FTDNA_FILTER;
  • declares only the IDs and INFO keys the file uses, and resolves conflicts with existing declarations.

The previous version of this command only deleted characters VCF forbids (Low Qual;q<10 became LowQual;q10), which could leave undeclared IDs or borrow the meaning of an unrelated declared filter.

A synthetic corpus of these cases (no donor data) is in tests/fixtures/ftdna_vcf/legacy_filters.vcf.
