AADR research-panel export

wgsextract microarray --input sample.bam --ref reference \
  --formats aadr_1240k,aadr_ho,aadr_1240k+ho \
  --aadr-sample-id sample01 --aadr-sex U --region chr20 --outdir out/aadr

Each selected panel writes both PLINK .bed/.bim/.fam and EIGENSTRAT .geno/.snp/.ind files. PLINK's SNP-major binary format is the standard compact interchange form accepted by PLINK and ADMIXTOOLS convertf; unlike .ped, it does not expand a single sample's million markers into a huge text row. No PLINK/ADMIXTOOLS installation is required to write these files.

The pinned AADR v66.p1 lists are GRCh37: 1,233,013 1240K markers and 584,131 HO markers. In this release HO is a strict subset, so aadr_1240k+ho (also aadr_1240k_ho) has the same markers as aadr_1240k. Provenance, licence and hashes identify the exact public SNP-only sources.

Opt-in AADR 2M (v66.p1)#

Install the marker resource explicitly, then select the additional panel:

wgsextract ref aadr --install --ref reference
wgsextract microarray --input sample.bam --ref reference \
  --formats aadr_2m --aadr-sample-id sample01 --outdir out/aadr-2m

ref aadr --install uses the existing resumable, shared-download mechanism and verifies the pinned SHA256 before installing reference/aadr/v66.p1_2M.aadr.patch.PUB.snp. The library can also be selected through the existing reference_library setting in config.toml. Pass the same library to the extraction (a FASTA under its genomes/ directory is also supported). The marker data are not bundled. microarray checks that the file is present and hash-correct before calling; it never automatically fetches or repairs it. For GRCh38 input, hg19ToHg38.over.chain.gz must also already be in the library: install it explicitly with wgsextract ref download --url https://hgdownload.soe.ucsc.edu/goldenPath/hg19/liftOver/hg19ToHg38.over.chain.gz --out reference/hg19ToHg38.over.chain.gz. T2T remains unsupported.

The 2M panel contains 2,142,271 GRCh37 SNPs, including every current v66.p1 1240K and HO SNP with the same ID, physical coordinate and reference/variant alleles. It is not the separate 1,243,531-site 2M_compatibility panel. It is excluded from --formats all; legacy panel choices and defaults are unchanged. Selecting aadr_2m,aadr_1240k,aadr_ho writes each panel separately. Absent sites in variant-only VCFs are no-calls by default. With the unsafe --assume-hom-ref --min-dp 0 --min-gq 0 opt-in, reference-fill eligibility is evaluated against the original legacy target set: a 2M-only hit cannot turn a previously missing legacy chromosome into homozygous reference. Sparse VCFs can therefore have different absent-site calls in the two panels under that opt-in policy.

Genetic maps are not interchangeable: the official 2M genetic distance differs at 1,200,251 legacy 1240K sites (583,490 HO sites). Each export uses its own panel's metadata, never a mixture: 2M .snp preserves the official v66.p1 2M Morgans, and .bim converts those values to centimorgans. Legacy 1240K/HO retain their existing map and bytes. Restricting a 2M export to 1240K therefore permits genotype comparisons but not byte-identical .snp/.bim metadata. For example, rs3094315 has 0.000665 Morgans in 2M versus 0.020130 in legacy 1240K/HO.

Source: Reich Lab AADR / Harvard Dataverse version 14.0, released 2026-06-08, panel v66.p1. The SNP-only file is 134,963,073 bytes, SHA256 39312150ce88ec757a88e52a7921ca7fd1190d9cce11cfe39c756ea5737b7a9b. It is published under CC0 1.0; cite the release and Mallick et al. (2024), Scientific Data 11, 182, doi:10.1038/s41597-024-03031-7. No individual genotypes, annotations or identifiers are installed.

Coordinates and allele coding#

  • .snp preserves AADR order, chromosome codes (X=23, Y=24), genetic positions in Morgans, GRCh37 positions, and reference/variant alleles. .bim uses the same order with A1=AADR reference and A2=AADR variant, converting Morgans to PLINK's centimorgans (column 3 multiplied by 100).
  • EIGENSTRAT .geno encodes copies of AADR's reference allele: 2=ref/ref, 1=ref/variant, 0=variant/variant, 9=missing. It is not ALT dosage.
  • PLINK .bed uses the documented SNP-major header 6c 1b 01 and the matching A1/A2 encoding: binary 00=ref/ref, 10=heterozygous, 11=variant/variant, 01=missing, with unused sample bits zero.
  • Calls are matched by normalized physical coordinate, not by rsID alone. An allele outside the AADR reference/variant pair is missing; no strand guessing, including at A/T and C/G markers, is performed. For VCF input, conflicting duplicate records and explicitly unsupported calls (including insertion genotypes) are masked directly from the per-record VCF calls, before any CombinedKit reference-filling assumption can affect AADR. This masking only removes calls; it never restores a quality-rejected call.
  • GRCh38 input uses the forward GRCh37-to-GRCh38 UCSC chain to locate each AADR marker. Only unique primary-contig hits are used; inverted mappings explicitly complement the call back to the AADR strand. Output remains GRCh37. Unmapped and ambiguous markers are missing. Unknown builds are not supported.
  • The existing CHM13 pathway can project legacy 1240K/HO through its bundled marker map. That map does not contain the full 2M panel: aadr_2m on CHM13/T2T is rejected before calling, rather than exporting unmapped new sites.
  • Haploid calls are represented as homozygous diploid dosage, as in the CombinedKit; this is not random pseudo-haploid sampling for ancient DNA.
  • A region-limited run still writes the complete selected panel, with missing calls outside the region. All markers without alignment calls are missing. The existing VCF-input semantics apply: by default, an absent variant on a represented contig may be treated as homozygous reference. A variant-only VCF is not evidence of coverage; use an alignment for coverage-aware no-calls.
  • The default sample label is sample, sex U, population Unknown, no parents or phenotype. Set a unique non-identifying --aadr-sample-id before merging. --aadr-sex changes metadata only, not the caller's ploidy inference.

The AADR target and calling intermediates are retained in a unique AADR_* subdirectory of the output directory for each invocation, isolating concurrent samples/builds/panels. The chain is reused read-only from the reference library when installed, otherwise downloaded into that invocation's directory for legacy-only runs. Runs selecting 2M require it in the library before any consumer-target preparation; even a chain left in an output directory is not treated as an installed 2M prerequisite. The intermediate CombinedKit and calling VCF also stay in that directory; the selected PLINK/EIGENSTRAT and vendor exports are written at the output root. Legacy cached consumer-chip targets are not modified. Mixing AADR and vendor formats adds the AADR sites to the run's target; all,aadr_ho explicitly includes the existing combined consumer target too. An explicit --ref-vcf-tab contributes additional sites to an AADR run. Without an AADR format, the existing target and output paths are unchanged.

Compatibility validation#

The authoritative allele/coding specification is ADMIXTOOLS convertf/README (EIGENSTRAT and PACKEDPED), and PLINK BED format. The export preserves the AADR reference allele, even if another tool would reorder alleles by frequency. Use PLINK's --keep-allele-order when preserving this coding is important.

Validation uses the public GIAB HG002 GRCh38 chr20 alignment, first at chr20:10,000,000–12,000,000, then all of chr20. It checks generated .snp metadata and .bim allele columns against all rows of the pinned public AADR .snp lists, and verifies that .bed and .geno encode the same calls. This is the metadata/allele-concordance alternative to a mergeit genotype merge: no AADR individuals' genotypes are needed or downloaded. Actual downstream merging is still subject to the other dataset's build, sample-label, SNP-selection and ploidy settings; no claim is made to reproduce ancient-DNA pseudo-haploid processing.

The chromosome validation checked every SNP metadata row with 100% exact ID/position/map/allele concordance against the public sources. Nonmissing calls also agree with the source caller VCF's AADR-reference dosage and the independently decoded PLINK BED representation:

One full-chr20 call has an out-of-panel allele and is correctly missing rather than forced into AADR's biallelic coding. Both runs preserve 23/23 legacy output files byte-for-byte (21 vendor formats plus both CombinedKit builds) against main 99eb6df. The built wheel is about 50.8 MB and contains the marker asset with the documented SHA256.

Focused tests cover reference dosage, missing/third alleles, haploid calls, conflicting coordinates, panel selection, exact BED bytes, safe metadata, inverted/ambiguous liftover and deterministic genotype-free asset generation. Existing consumer formats are additionally compared byte-for-byte with main on the same public chromosome input.

Targets not fabricated#

MTHFR Genetics, Genera and meuDNA need a verifiable real export or public complete marker list, schema, build, strand and reuse terms. No such input was verified in the available local inventory. GEDmatch already accepts the combined 23andMe-style kit; no new fixed GEDmatch panel was verified. These are not aliases to unrelated vendors and are not invented templates.
